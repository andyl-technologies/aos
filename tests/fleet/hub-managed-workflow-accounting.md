# Complete Managed application-body accounting

The called Managed controller starts its outer capture before container and
private-document publication. It retains four independent original/received
proxy records, their four protected-header files, and the actual Native and
Worker log prefixes. It ends after the real GC and terminal-cleanup controllers.
Startup before that business interval has its separate installation receipt.

## Actual process epochs

The current Native, Worker, and two proxy process pins are checked at both ends
of each business epoch. Before a Worker stop, the caller closes that epoch while
its original process is live. The next begin observes the actual replacement
pin and retains the intervening file ranges as startup. Every original and
received row must belong to exactly one epoch or startup interval. All intervals
must partition the independently retained complete prefixes without overlap,
substitution, unassigned suffixes, or reused actual transport call IDs.

The profile-refusal Worker B has its own process, configuration and log facts;
it is recorded as an auxiliary transition. It is never substituted for Worker
A. Restored A must append the original Worker log inode. Closing the last epoch
without a live final capture, a missing transition, or a failed recheck keeps the
whole assessment incomplete.

One-shot cleanup helpers have separate real PID/start/executable/argv/environment
and private input/output/stdout/stderr/lifetime receipts. Two read-only upstream
authentication children additionally require their actual startup nonce/PID
ready/release references and complete bounded output. Neither child contributes
Native consumed bytes. A completed response at the loss listener remains
distinct from the lost dispatch's actually exposed Native response chunks.

## Current state and provider reads

The terminal controller uses the existing confined PostgreSQL reader to observe
the exact upload, chunk, placement, binding/current write revision, and Delete
capability arrays before and after each helper invocation. The query selects
the original placement even after successful settlement clears upload locators.
Canonical compact UTF-8 JSON hashes must match the actual post-authentication,
post-final-Delete-check event. Its completion must lie inside both the helper
lifetime and independently observed SQL brackets. Settlement permits only the
existing resource-version advance and exact cleared locators; it cannot change
the immutable original or other four tuples.

The Worker emits a do-e2e-only read completion after the existing conditional
GET incarnation checks, actual EOF, counted size, SHA-256 comparison, and cutoff
check. It contains the actual consumed bytes, hash, strong ETag and opaque upload
version. The collector joins it to that request's actual GET result. Premature,
duplicate, unknown, foreign-scope, or missing completion refuses coverage.
Ordinary builds keep the observation wrapper empty. Provider permissions,
read/deletion ordering, pending fences and cleanup authority are unchanged.

A positive metadata subset requires independently inventoried upstream
authentication, the same-source held decoder, actual Native consumed bytes and
post-authentication receipt, final Delete context, current SQL, exact physical
result/EOF incarnation, and that fresh replay/settlement's complete zero-call SDK
bracket. The first positive physical response cannot substitute for either
fresh bracket or Native consumption. Installed OCI purpose/profile verification
is retained separately and never becomes a Delete capability.

The whole consumer also reopens the already-retained genuine GC positive report
and reruns its existing exact SQL-action/SDK/guard join. It performs no new query
or provider work. That report does not fill missing consumption, purpose or
authority observations for other execute calls.

## Bounds and final gate

The observation ceilings remain 204,704 rows per raw role, 48 KiB per row,
512 MiB per raw retained file, and 16 stable business epochs. They are retained
observation bounds, not protocol guarantees or measured call budgets. Raw files
are streamed through a bounded row buffer. Retained row metadata is limited to
1 KiB per row and a 256 MiB encoded summary per collection of four proxy roles.
Combined epoch summaries and exact final JSON representations separately have
256 MiB limits. This bounds stored metadata and collection counts; it is not a
measurement of Python allocator overhead or whole-process RSS.

The final JSON encoder enforces its exact byte limit incrementally before
persisting an aggregate. Overflow retains a bounded incomplete diagnostic and
all already-retained raw prefixes. Missing, refused, substituted, unsupported or
partial joins remain in the original inventory. Nothing drops such a row to
make a positive subset complete.

The caller retains the final conclusion and requires complete coverage before
normal return. A producer exception remains the original exception even when a
separate capture/join fails; both failure classes are retained. No status,
signature hash, configuration, caller Boolean, empty workload or supplied digest
establishes authentication or a numeric Native bulk conclusion.

## Required final-source dependencies

The fixture modules selected in the same managed module bundle are
`managedWorkflowAccounting` and `managedCleanupSql`. Existing cleanup accounting,
GC SQL/collector and current codec selection/provenance remain mandatory. The
caller hunk is composed against Fleet's explicitly pinned profile-transition
caller, separately from its other module/Nix changes.

The final runtime still requires the approved source-produced Native ingress
acceptance/refusal observations for the actual authorize, preflight, complete
and read branches. Compact assertion shape alone does not supply current IAM.
Actual probe, index and read execute operations beyond the four GC codecs need
their exact current shared decoder and accepted-consumption/context joins.
Those are mandatory source followups; this consumer currently retains them as
unresolved and stops completion. External helper services also require their
own full lifetime and original transport inventory.
