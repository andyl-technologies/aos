# Managed cleanup application-byte observations

The called terminal-cleanup controller joins the normal Native service and the
separate Native helper invocations to the complete retained proxy windows. It
executes the selected current storage-body codec for correlated positive calls.
It does not use an upstream-completed physical reply as a Native-consumed reply.

## Selected inputs and call

Include `_hub-managed-cleanup-accounting.py` in the same installed fixture module
bundle and set `tools['managedCleanupAccounting']` to its immutable module path.
The existing terminal controller calls
`account_managed_cleanup_windows(native, tools, prepared, boundaries, result)`
after the loss, cold replay and settlement windows finish. Its result is retained
as `result.nativeApplicationAccounting` and in a separate private accounting file.

The current selections remain explicit: `commonSourceStorePath`,
`workerSourcePath`, `managedCleanupNativeHelper`,
`managedCleanupNativeHelperProvenance`, and
`boundaries.codecSelection`/`codecProvenance`. A prior observer executable is not
a replacement for this tuple. The helper ELF and its provenance are checked
against actual installed bytes before its retained invocation is read.

Each SQL-selection, dispatch, replay and settlement helper has its own actual
PID/start/UID/executable, raw command/environment references, input/output,
stdout/stderr and completion brackets. Its PID cannot stand for the concurrent
Native service. The private stdout subscriber rows must equal the actual helper
output, within the existing 64-row/32-KiB subscriber limit. Readonly and upstream
authentication phases must contain no Native exchange observations.

Exact call IDs correlate offered body hashes and Native-exposed reply counters
to post-authentication receipts, the final Delete-checked context and the two
independent proxy captures. Ownership is exclusive across all three windows,
including concurrent service calls. Every original remains assigned or
explicitly unresolved; extra received rows, authentication receipts and numeric
calls remain recorded. Complete inbound inventory commitments and raw windows
are also retained.

## Bounds and custody

The private invocation/input/output files are capped at 64 KiB each, raw command
and environment at 64 KiB each, stdout at 128 KiB and stderr at 64 KiB. Their exact
owner-private regular files, link count, size, identity and SHA-256 are checked
without following replacements. Raw private values are not returned in the
projection.

Proxy windows keep the existing 512-MiB log, 48-KiB row and 204,704-row observation
ceilings. Their complete retained hashes are verified with a 64-KiB buffer,
followed by the existing streaming header parser. Combined body/header/event
summary inputs have a 256-MiB serialized budget and global row ceilings; the
controller reuses bounded window references rather than copying raw logs.
The exact final report representation is checked against the existing 256-MiB
retained-report ceiling before persistence. Overflow retains a bounded incomplete
diagnostic and all pre-existing raw windows. These are observation limits, not
protocol limits, measured RSS or production call budgets. Codec per-invocation,
body, aggregate-reference and global segment-ownership limits are unchanged.

## Incomplete obligations

`complete` and `nativeBulkBytes` remain false/unknown. Independent current SQL/API
state, installed purpose acceptance and complete provider partitions are still
required; a parsed hash, status, signature framing or supplied dictionary cannot
satisfy them. The two upstream-only authentication helpers currently have no
independent invocation pins, so their lifetimes are listed as unresolved
auxiliary inventory. They do not supply Native transport rows. Lost, partial,
missing and unsupported bodies do not become zero-byte classifications.

The focused Python gates exercise real private-file custody and the called
controller with controlled callback records. They establish neither a deployed
Native/Worker process nor actual MAC/IAM/SQL/provider qualification. Existing
capture/context/window regressions are retained. The actual fleet still requires
one reviewed common source, matching installed helper/codec/assets, complete
machine/service/helper windows and independent acceptance/provider joins. Counts
describe offered and exposed application payloads, never TLS wire billing.
