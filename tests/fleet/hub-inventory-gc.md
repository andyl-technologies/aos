# Selected External OCI inventory and GC

This additive helper is intended for the normal selected fleet controller. It
does not launch a second controller or qualify terminal private-upload cleanup.
Its local tests check helper refusals only; a real runtime tuple and actual
provider observations are still required.

## Prerequisites

1. Retain a genuine canonical OCI publication and its current SQL placement,
   binding, write revision and mutation epoch. Run the existing placement scan
   and bounded OCI inventory controller. Complete inventory must contain actual
   portable SHA results for every object and real immutable provider versions.
2. Independently review the selected provider's versioned conditional-delete
   contract. A Write or upload result supplies no Delete qualification. Export
   `delete-cohort.json` using `aos-hub-authority-bootstrap export-delete-cohort`
   from the existing SELECT-only database connection and validated issuer
   configuration. The Rust helper derives the Delete-only selection from the
   actual admitted publication and rechecks the current head before publishing
   private canonical output; it grants no new admission or signing authority.
3. Install that exact selected cohort and contract pin through the existing
   operator path. Wait for the real conditional-delete capability controller's
   valid record under the exact binding revision and independently held Delete
   credential. A missing or `null` provider version remains unsupported; the
   positive case must use a genuinely contract-conformant emulation input or
   remain incomplete. Never stamp capability from provider type or upload success.
4. Retain the offered/received control bodies, actual SQL projector rows and
   independent provider observation windows. No Native bulk-byte conclusion
   follows from a zero-initialized counter. That requires its own authenticated
   shared-codec body and operation/context joins.

## Cases required before qualification

- Apply an actual reviewed retention policy, then wait for a complete inventory
  at its new mutation epoch. Review GC through `ContainerService` and retain the
  server's exact plan, confirmation, candidates and placement actions.
- Between review and Apply, root one selected object through its ordinary API.
  Apply must refuse and an independently complete provider window must contain
  no DELETE. Repeat with actual placement/binding or source/inventory drift;
  never patch the review original or clear unknown physical state.
- For a fresh unrooted candidate, Apply the genuine plan and let the existing
  GC controller obtain its actual action claim and frozen credential custody.
  Require real run completion and join each final action to its exact admitted
  conditional request, positive permanent guard receipt and exact-version
  absence observation. A caller status or unknown result cannot replace these.
- Replay the same original without repeating provider deletion. Changed or
  unrelated provider replies must fail closed. Retain all prior refused or
  unknown outcomes; private upload cleanup belongs to its separate owner.

`_hub-inventory-gc.py` provides the bounded read-only inventory selector and
normal API orchestration. The selected runtime installation, semantic receipt
joins and positive provider case are pending reviewed fleet composition; the
helper has no automatic activation in the main flow.
