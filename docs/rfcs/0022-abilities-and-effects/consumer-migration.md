# Consumer migration handoff

The native cutover is in progress on the same PR. This checklist records the
remaining integration and qualification work; it does not establish whole-system
readiness. Superseded APIs are removed with their callers, without compatibility
adapters between unreleased designs.

## Current implementation

The package recipe companions, native evaluator, typed graph checker, durable
activation controller, and generated documentation are implemented. Package
consumers now include service management, configuration, networking, identity,
filesystem and storage, databases, orchestration, and execution observation.
APM uses native evaluation and profile transactions; boot and package operations
share the system profile path. Rollback replays a retained desired deployment as
a new transaction rather than rewinding the execution journal.

Hub release ingestion, indexed package documentation, deployment reports, and
CLI inspection now read native documents. The old inspection crate and its
provider-plan projections have been removed; standalone realized artifact-use
evidence remains a separate feature.

Focused Nix, Rust, and handler tests cover these paths. Remaining integration
work includes initial authorized host-source adoption, exact image/source replay
for all selected image features, and qualification callers with independently
observed domain evidence. Native image staging, rollout submission, finalization,
and source-built evaluation/GC/materialization checks have focused coverage;
combined boot and physical transition checks remain separate. Passing schema or handler unit tests alone does
not qualify an image boot or physical image transition.

Read the [target state](13-target-state.md),
[infrastructure APIs](infrastructure-cutover.md), and
[code examples and execution paths](../../users/aos/runtime-abilities.md) first.

## Infrastructure to use

- Recipe: `module = ./directory` containing `module.nix`, plus `moduleDeps`.
- Distribution: `deploymentArtifact/deployment.json` and
  `documentationArtifact/options.json`, both generated by the builder.
- Evaluation: `lib.evalPackageModules`, using the retained
  `lib.packageModuleLibrary` for deployment-time evaluation.
- Resolution: `aos-package::deployment::evaluation::{PackageResolver,
  resolve_packages, Evaluation}`. Supply authenticated, already-realized package
  envelopes and exact immutable module sources.
- Runtime: `aos-ability-plan::module_graph`,
  `aos-ability-runtime::activation`, and
  `aos-package::deployment::transaction::Transactions`.
- Artifact retention: `deployment::retention::{ArtifactAdmission, NixStore}`.
- Documentation: `aos-doc-model::runtime::RuntimeDocument`, shared by
  `aos docs runtime`, signed package references, Hub indexing, and its native viewer/API.

The working integration fixture is `tests/effects/deployment-fixture.nix`;
`crates/aos-package/examples/package_deployment_check.rs` exercises the entire
infrastructure path. Use that path directly rather than the older
`config_eval` provider-discovery and registry-projection machinery.

## 1. Domain interfaces and package modules

Inventory `abilities =`, `configModule`, `.contract`, `requirementTemplates`,
`implementations`, `compositionRequests`, and old provider/binding records under
`pkgs/`, `modules/`, `systems/`, tests, and the Rust consumers. Record each live
owner before deletion; a search match may also be a historical document.

Move domain contracts and lowering to their owning package or system feature.
Keep `lib/` generic. For each domain, declare input/result modules once, expose
ordinary user options by reusing those modules, and derive enabled effects from
the merged config. Independent modules must be able to extend the same instance.
Do not add empty instance boilerplate, parallel interface maps, manual revision
counters, package-name dispatch, or hand-maintained documentation tables.

Convert handlers to retained `program` artifacts or typed child compositions.
Review whether each effect needs instance, transaction, or persistent lifetime.
Implement observation and teardown against the actual backend; do not hide
ordering in a catch-all activation shell script. Preserve backend features such
as service dependencies, reloads, credentials, and isolation rather than
flattening the interface to a minimal init system.

Start with one small complete domain, validate its package/handler/operator
composition, then migrate the remaining domain owners. Keep the native API fixed
unless concrete consumer evidence reveals a missing generic requirement.

## 2. Publication, APM, and retained generations

Switch release assembly and metadata to retain exact native envelopes, module
sources, dependency edges, and generated references alongside payloads. Preserve
existing release authentication and artifact admission. Module source and payload
identity must survive transfer to another immutable store view.

Replace installed-package evaluation/planning with native resolution and
`Evaluation`. Feed its checked deployment into `Transactions`; resume pending
work before accepting another generation. Make the committed generation journal
the authoritative pointer and reconcile any external profile links with it.
Wire removal, reconfiguration, rollback, and generation pruning to these APIs.
Do not recreate the same state machine in CLI code.

## 3. Boot, images, and OS runtime

Move image and boot entry points to native module selection and the same package
transaction machinery. Images must retain the selected module library, package
sources, payloads, and handlers needed to reconstruct the intended scope.
Make early-boot ordering explicit, including which primitives must already exist
before the package runtime can run. Validate that resumed boot does not replay
completed transaction-lifetime operations.

Keep the previously agreed smaller package-managed container base: select a
package/module slice explicitly from the broader image definition. Do not
implicitly copy every server package into a container. This handoff does not
port kernels, toolchains, or the Linux process transport.

## 4. CLI and Hub release/documentation consumers

Hub's `/-/runtime-abilities` page and `/-/api/runtime-documentation` endpoint
inspect supplied artifacts. Authenticated release ingest, indexed package pages,
and deployment reports also use the shared native document model. Keep the
artifact import viewer's caller-supplied context distinct from a signed release.

Validate installed-package docs, Hub release metadata/ingest, search indexes,
package pages, and deployed-system inspection against the native documents. Preserve
release coordinates and provenance when linking packages, operation declarations,
selected handlers, and configured uses. Source native renderings from the shared
reader; extend its view model where necessary rather than creating another
schema parser per client. Keep observed runtime state separate from desired
configuration and static package declarations.

Remove obsolete docs/ability projections and old provider-plan inspection
surfaces once their last consumers have moved. Update examples and navigation
in the same commits. Do not leave a second legacy reader marketed as the current
native system.

## Acceptance and stopping points

- A domain option extended in two files merges through ordinary modules and
  yields one owned effect, with generated documentation from the same declarations.
- A package publishes, transfers, evaluates, activates, reconfigures, removes,
  and recovers using native artifacts and state machines.
- Missing handlers and incompatible result references fail before mutation.
- CLI and Hub link exact release/package ownership to the same native reference
  and graph, without copied ability catalogs.
- Boot and the reduced container scope exercise the native path with their real
  handlers; infrastructure-only checks are not a boot qualification claim.
- Obsolete public fields, private adapters, duplicate schemas, and stale current
  documentation are removed after the final consumer switches.

Iterate with Cargo through `aos-dev` first, then use focused Nix checks and builds
through `aos-dev` with the shared cache. Begin with `checks.effects` and the
package deployment example. Broaden to domain and boot/image checks as their
consumers migrate. Avoid treating a long-running monolithic evaluation as useful
feedback; isolate its expensive dependency before continuing.

Bounded journal storage currently has no automatic compaction. That is an
explicit infrastructure limitation, not something generation pruning solves.
