# Resolved decisions (F1–F3 + formerly open questions)

The adversarial-review forks and the generations open questions are resolved here with locked choices + decision-free mechanisms (produced by the execution-readiness pass). These supersede the "open" framing in [`known-issues.md`](known-issues.md).

## F1 — Anchor the on-host evaluator + base lib to measured boot via dm-verity on the erofs root with the roothash on the measured UKI cmdline

**Decision.** Adopt Option A: dm-verity-protect the read-only erofs root (which carries the base lib + evaluator closure) and bake the dm-verity root hash into the UKI's `.cmdline` PE section, so it is measured into PCR 11 and covered by the existing signed PCR policy and the whole-PE Authenticode signature. Reject B (embed-in-UKI initrd) and C (scope-down). The root hash binds a UKI to exactly one root image: tampering the root either fails dm-verity at read time (boot fails closed) or requires a new root hash → a new `.cmdline` → a new PCR 11 that the sealed-`/var` policy will not bless and that the db-signed UKI signature will not cover. PCR 11 therefore transitively covers the producer (evaluator + base lib), closing the C1/F1 gap.

**Rationale.** A composes with the existing measured-boot stack instead of fighting it. The seal mechanism (`modules/base/secure-boot.nix` `aos-var-crypt`) already binds `/var` to PCR 11 (signature-flexible, signed by the release PCR-policy key) + PCR 7 (pinned). PCR 11 measures the UKI's `.cmdline` section (sd-stub measures the UKI PE sections), and the signed PCR policy in `.pcrsig` is computed by ukify over those same sections (`pkgs/boot/aos-uki.nix` `--pcr-private-key`). So putting the roothash on the cmdline rides entirely inside an already-measured, already-signed surface — no new PCR, no new seal step, no change to the OTA-survival property (a new image ships a new UKI signed by the same policy key, whose new PCR 11 — including the new roothash — is policy-blessed, so `/var` still unseals). The repo already has every building block: `lib/build/package-root-image.nix` does exactly the needed reproducible `veritysetup format --salt <pinned> --uuid <pinned>` + roothash extraction + `openssl cms -sign` over the ASCII-hex roothash, and `lib/testing/package-root-image.nix` already gates that the two-build roothash/signature are byte-identical and that a tampered block fails `veritysetup verify`. The erofs root is already byte-reproducible (`lib/build/rootfs.nix`: `mkfs.erofs --all-root -T0 -U <fixed> --workers` is deterministic across worker counts), so a pinned-salt/uuid verity tree over it yields a deterministic roothash — the UKI stays byte-reproducible. systemd's verity userspace is confirmed present and unstripped (`lib/testing/systemd-verity.nix`: `systemd-veritysetup`, `systemd-veritysetup-generator`, `veritysetup.target`). B is rejected because it inflates the initrd with the whole base-lib+evaluator closure and reintroduces the documented initrd→toplevel→initrd cycle (`lib/build/rootfs.nix` header). C is rejected because it leaves the stated attack open (offline root write swaps the evaluator with no PCR movement and `/var` still unseals). The `gen-attestation` record's `inputs.base_lib.pcr11_expected` (trust-and-secrets.md) only becomes truthful under A — it is otherwise a PCR that demonstrably does not cover the root.

**Mechanism.**

Build side (all sandbox-compatible, no losetup/mount; reuse `lib/build/package-root-image.nix`'s verity recipe):

1) `lib/build/rootfs.nix`: add a gated `verity` mkfs sub-step (param `verity ? false`, set true only for the production erofs path; ext4/VM-test images unchanged). After `root.img` is finalized, run `veritysetup format --salt "$SALT" --uuid "$VUUID" root.img root.verity`, parse `Root hash:` into `root.roothash` (validate `^[0-9a-f]{64}$`), and when an SB db key is supplied (deployment overlay) `openssl cms -sign -binary -in root.roothash -signer $CERT -inkey $KEY -outform DER -out root.roothash.p7s -nosmimecap -noattr` (identical to package-root-image.nix). Derive `$SALT`/`$VUUID` deterministically from the image identity via the existing `mkUuid`/substring-of-sha256 seed pattern so the roothash is reproducible. Emit `$out/{root.verity,root.roothash,root.roothash.p7s,root-verity-size-bytes}` alongside `root.img`. erofs needs no shrink/normalize step (it is content-sized and already `-T0 -U` fixed), so the hash tree is over stable bytes.

2) `pkgs/boot/aos-uki.nix`: add optional arg `rootHashFile ? null`. In the build phase, when set, append the build-time hash to the materialized cmdline before ukify: `printf '%s roothash=%s' "${cmdline}" "$(cat ${rootHashFile})" > cmdline`. This is the load-bearing trick: the roothash is a build-output (Merkle root of root.img), unknowable at Nix eval, so it cannot travel through `aos.boot.kernelParams`; it is injected here into the same `.cmdline` section ukify measures (`--pcr-private-key`) and the db key signs — so the roothash is simultaneously in PCR 11 and under the Authenticode signature.

3) `modules/image/_builder.nix`: (a) thread `rootHashFile = "${rootfs}/root.roothash"` into the `pkgs.aos-uki { ... }` call; (b) add partition 3 `root-a-hash` to the GPT — size it from `${rootfs}/root-verity-size-bytes`, place it immediately after `root-a` in the `sfdisk` table and `dd` `root.verity` into it, bump `disk_sectors`/`root_start_sector` accounting, and record it in `image-info.json` (leave trailing free space for ignition's var/swap/root-b as today). Use the Linux-filesystem type GUID (or the DPS root-verity GUID `2c7357ed-ebd2-46d9-aec1-23d437ec2bf5`); device discovery is by partlabel so either works.

Eval side (kernel params + initrd; via `modules/security/verity.nix`, rewritten):

4) Replace verity.nix's dracut-style `verity.data=/verity.hash=/verity.roothash=` params (wrong for a systemd initrd) with the systemd-veritysetup-generator params: `aos.boot.kernelParams += [ "systemd.verity=yes" "systemd.verity_root_data=/dev/disk/by-partlabel/root-a" "systemd.verity_root_hash=/dev/disk/by-partlabel/root-a-hash" ]`. Drop the eval-time `rootHash` option entirely from kernelParams (it is supplied by the build-time UKI append in step 2; the generator unions `roothash=<hex>` from the cmdline with these device params to assemble `/dev/mapper/root`). Keep `dm_verity` in `aos.boot.initrd.modules`.

5) Make `root=` follow the mapper device. Parameterize `modules/base/boot.nix`'s hardcoded `root=/dev/disk/by-partlabel/root-a` off `config.aos.filesystems.rootDevice` (default it to `/dev/disk/by-partlabel/root-a`), and have verity.nix set `aos.filesystems.rootDevice = "/dev/mapper/root"` (and the matching fstab device in `modules/base/filesystems.nix`). This flips `root=` to the verity-assembled device without mkForce list surgery. Also guard ignition's grow-root unit (`modules/services/ignition.nix`) to ext4-only (`rootFsType == "ext4"`): an erofs+verity root must never be grown, since that would change bytes and break the roothash.

6) Production wiring (implemented): `systems/server-verity.nix` imports `systems/server-measured-boot.nix`, inherits the server profile's erofs root, and sets `aos.security.verity.enable = true`. The image builder derives `verity = true` from that option. Ordinary VM tests may keep ext4 + verity off; `checks.fleet.measured-boot` exercises the production-integrity variant.

PCR-11-covers-root proof: sd-stub measures `.cmdline` (now containing `roothash=<hex>`) into PCR 11; `<hex>` is the Merkle root over every byte of the erofs root carrying base-lib+evaluator. To make a tampered root mountable an attacker must change `<hex>` → change `.cmdline` → (i) break the whole-PE db Authenticode signature (enforcing SB firmware refuses to load it; attacker lacks the db key) and (ii) change PCR 11 to a value the signed PCR policy does not bless (attacker lacks the release PCR-policy key), so sealed `/var` will not unseal. Tampering without changing `<hex>` is caught by the kernel dm-verity target at first read (EIO) → fail closed. Note the anchoring needs only the roothash-on-cmdline (key-independent), so the unsigned base image stays reproducible and key-free; the optional `root.roothash.p7s` reuses the SB db key for in-kernel roothash-signature enforcement and is what the existing `pkgs/security/aos-verity-root-guard.nix` validates against the SB db.

Reproducibility/A-B: roothash is a deterministic function of the reproducible erofs image given pinned salt/uuid (already gated identical-across-two-builds by package-root-image checks); the UKI stays byte-reproducible. The P0 byte-identical-toplevel gate is unaffected (the UKI/image layer is below toplevel). A/B is naturally supported because the roothash-on-cmdline makes each UKI self-describing about its root: slot A = {root-a, root-a-hash, UKI-A(cmdline→hash-A)}; a sysupdate slot B builds {root-b, root-b-hash, UKI-B(cmdline→hash-B with `systemd.verity_root_*=…root-b*`)}. The only A/B follow-on (sysupdate-side, not blocking F1's first-boot install which ships slot A) is making the device partlabels per-slot in the B-slot UKI's cmdline.

Seal/attestation changes: seal mechanism unchanged — still PCR 11 (signed) + PCR 7 (pinned); the roothash rides inside PCR 11 for free, no new PCR/step. `apr publish --image <uki>` (RFC-0006 phase 4) already records the ukify-predicted PCR 11 from the signed UKI; because the roothash is in that UKI's cmdline, the recorded `expected_pcr11`/`base_lib.pcr11_expected` now genuinely covers the root. Extend the `gen-attestation` record (trust-and-secrets.md) `inputs.base_lib` with `root_verity_roothash=<hex>` (and optionally the verity partition UUID) so a verifier can independently confirm the booted UKI's cmdline roothash matches the published image's root.

## F2 — On-host rendering of shell-snippet service options (script/preStart/postStart/reload/preStop/postStop)

**Decision.** LOCK F2-A. The manifest carries each job script's TEXT (never a built `unit-script` derivation); the APM materializer writes the texts to generation-local paths and rewrites the `Exec*=` assignments to point there. `makeJobScript` (`lib/modules/systemd/unit-options.nix:644` / `lib/modules/systemd/lib.nix:691`) stops calling `pkgs.writeShellScriptBin` and instead records `{ key, text, mode }` records into a top-level `manifest.jobScripts` map, emitting a stable placeholder token into the unit's `Exec*` line. F2-B (banning these options) is rejected: it is a real language restriction that falsifies "evaluates identically on either evaluator."

**Rationale.** script=/preStart=/postStart=/reload=/preStop=/postStop= compile through `makeJobScript` → `pkgs.writeShellScriptBin` → a derivation whose built `/nix/store/...-unit-script-*/bin/*` path is currently interpolated into `Exec*=` by `attrsToSection def.serviceConfig` (`lib.nix:986`, via `serviceToUnit`). The script body is a function of the *evaluated* stage-2 config, so it cannot be pre-built in stage 1, and an eval-only host must not build it (invariant 1). Carrying text and materializing it imperatively is the only option that (a) keeps the full systemd module language so the same modules evaluate identically on stock Nix and aos-nix, and (b) keeps materialization in the "assemble already-present bytes, no compiler/configure/derivation-realization" category that the architecture's render/assemble split requires. The cost — `Exec*` bytes differ from the build-time `writeShellScriptBin` path — is absorbed by a text-equality golden comparator, which is cheaper and safer than amputating `preStart` from the language.

**Mechanism.**

SCHEMA — `manifest.jobScripts` is a flat map. Key = `"<unitName>:<ExecSlot>.<index>"`: `unitName` the full unit (e.g. `redis.service`); `ExecSlot` ∈ {ExecStart, ExecStartPre, ExecStartPost, ExecReload, ExecStop, ExecStopPost}; `index` the 0-based ordinal of this entry within that slot's final `serviceConfig.<Slot>` list (option-derived scripts are always `.0`). Value = `{ "text": "#!/bin/sh\nset -e\n\n<snippet>\n", "mode": "0755", "name": "<scriptName>" }` where `<snippet>` is the evaluated option string and `name` is the sanitized short name (`replaceStrings ["\\" "@"] ["-" "_"] (shellEscape name)`) kept only for logs. No store paths, no context.

REROUTE makeJobScript (lib.nix:691) — drop the `pkgs.writeShellScriptBin`/`.overrideAttrs`/`lib.getExe` body entirely. New signature `makeJobScript = { unit, slot, index, name, text, args ? "" }:` returning a pure record `{ key = "${unit}:${slot}.${toString index}"; name = <sanitized>; text = "#!/bin/sh\nset -e\n\n${text}\n"; mode = "0755"; placeholder = "#aos-jobscript:${key}#" + lib.optionalString (args != "") " ${args}"; }`. At the six call sites (unit-options.nix:644-687) each `mkIf` block (a) appends the record to the unit's `jobScripts` option, and (b) sets `serviceConfig.<Slot> = lib.mkDefault [ <record>.placeholder ]` (the `script=` case threads `args = config.scriptArgs` so the placeholder is `"#aos-jobscript:<unit>:ExecStart.0# <scriptArgs>"`; all others pass no args). Retype the `jobScripts` option (unit-options.nix:610) from `coercedTo path singleton (listOf path)` to `listOf (attrsOf str)` (the record), keeping `internal = true`. The placeholder token is a single whitespace-free lexeme so it serializes cleanly through `attrsToSection` and is unambiguous in `Exec*` bytes.

AGGREGATE — `modules/base/build.nix`, where the `/etc`/units assembly is rewritten to emit the `aos.config-manifest/v1` value, folds every unit's `config.systemd.<type>.<name>.jobScripts` records into the single top-level `manifest.jobScripts` keyed by `record.key` (collision = eval error; keys are unique by construction). The rendered unit bytes in `manifest.etc["systemd/system/<unit>"]` contain the placeholders verbatim.

GEN-LOCAL PATH SCHEME — for key `<unit>:<slot>.<idx>` the materializer writes `<GEN_DIR>/job-scripts/<unit>/<slot>.<idx>` (e.g. `gen-7/job-scripts/redis.service/ExecStartPre.0`), `chmod` to `mode`, where `<GEN_DIR>` is the activating generation directory APM already creates for `gen-N/manifest.json`. The path is absolute and generation-scoped, so each generation's unit files reference that generation's own scripts; rollback (re-point the profile) is self-consistent with no re-render.

EXEC REWRITE — during materialization (the imperative assemble step in `crates/aos-package`, alongside `config_artifact.rs`/`exposed_units.rs`, before `mkfs.erofs` of the `/etc` lower): for every `manifest.etc` unit file, byte-substitute each occurrence of `#aos-jobscript:<key>#` with the absolute `<GEN_DIR>/job-scripts/<unit>/<slot>.<idx>` for that key; any trailing ` <scriptArgs>` already present in the line is left untouched and follows the substituted path. This is pure deterministic string substitution over already-present bytes (no build). The materialize step must fail closed if a placeholder has no matching `manifest.jobScripts` entry, or a `jobScripts` entry is never referenced.

GOLDEN NORMALIZATION — `lib/testing/system-characterization.nix` comparator normalizes every `Exec*=` value to its referenced script TEXT before comparing: for the master (pre-P0) form it resolves the embedded `/nix/store/...-unit-script-*/bin/*` path to the script body (reads `text`/file content); for the F2-A form it resolves `#aos-jobscript:<key>#` via `manifest.jobScripts[key].text`. Both reduce to `ExecStart=<SCRIPT-TEXT>[ <args>]`. Equality is on this normalized stream — semantic (text) equality, not embedded-path equality. The committed golden stores the normalized form; the placeholder-vs-store-path divergence is the single documented intentional P0 byte change.

PUBLISH-LINT — extend the publish-time probe-eval that already checks the provides/requires interface (module-system.md; promoted from `pkgs/build-support/_expose-renderer.nix`). Over each package's `config` output it `builtins.deepSeq`s the rendered config value, then fails publish if (1) any reachable sub-value satisfies `lib.isDerivation` (an attrset with `type == "derivation"`), or (2) `builtins.getContext` of any rendered string contains an entry that references a `.drv` path or requests outputs (`outputs`/`allOutputs` keys) — the context signature left only by interpolating a derivation. Plain bare store-path strings (path context, no `.drv`, no outputs) are permitted, matching the string-path discipline. A `writeShellScriptBin`/`writeText`/`mkDerivation` reference in a `config` output is therefore a publish failure, not a silent on-host build attempt.

## F3 — Conscription vs composition authorization

> **Amended 2026-07-21 (index removal) — see [F3-B enforcement-locus amendment](#f3-b-index-removal--enforcement-moves-to-resolve-time-systemroots-2026-07-21).** The F3-B *authorization model* (capability-scoped contribution surface via the `contributable` marker) stands. Its *enforcement locus* changes: the publish-time registry-index checks described below are superseded by per-system, resolve-time enforcement against the locally-derived `SystemRoots`. Where the mechanism below reads "publish-time authorization pass", `index.rootOwner`, or `index.surface`, substitute the amendment's `SystemRoots`-based, resolve-time model. The paragraphs are retained for provenance.

**Decision.** LOCK F3-B: capability-scoped contribution surface. A shared-root OWNER curates, in its own option declarations, which sub-paths non-owner packages may write into. Authorization is per-option, encoded as a `contributable` marker on `mkOption`, carried as per-package metadata (`OwnedRoot.contributable`), and enforced by the resolver at resolve time against the installed owner's contributable surface (see the 2026-07-21 amendment; the original publish-time registry-index enforcement is superseded). Foreign writes that land under a contributable sub-path are allowed (composition); foreign writes to any non-contributable path of a shared root — notably `enable` and global owner-only fields — are rejected (conscription). The operator (host.nix) and the root's own owner are exempt from the check; foreign service-enable remains a resolve-time assertion.

**Rationale.** F3-A (operator-grant) forces operator wiring for ordinary apps; F3-C (strict-forbid) makes the operator hand-wire every nginx↔nextcloud edge — both push burden onto the operator for what is routine composition. The unscoped "registered contributor" escape rejected in the conscription section is exactly an attacker's move because it is all-or-nothing per root. F3-B makes "contributor" non-vacuous by scoping it per-option/per-subtree, curated by the party that owns the merge semantics (the owner already declares the schema and merge for the shared root, so it is the correct authority for what is safe to extend). The mechanism rides existing machinery with no new evaluator capability: `mkOption` already stores arbitrary declaration fields (lib/modules.nix:47-75), `collectOptions` already carries the whole `option` record per path (lib/modules.nix:251-257) so the flag is visible at `optionMap.${key}.option` (lib/modules.nix:657-664), and the publish-time options-only eval that already derives `provides` (module-system.md:64-71) extends trivially to emit the flag. Provenance is taken from the resolver-stamped authenticated identity, not module `_file` — required by M-forgeable-file, since `collectDefsAtPath` threads a forgeable `file` (lib/modules.nix:298-328,669) that a package could set to host.nix or to the owner identity.

**Mechanism.**

OWNER DECLARES THE SURFACE (per-option marker, subtree-inheriting with holes):
1. Add `contributable ? false` to `mkOption`'s arg set and to its returned attrset (lib/modules.nix:47-75), alongside `readOnly`/`internal`. It is a pure declaration field; the merge engine ignores it (no change to phases 3-5). Default false = owner-only.
2. The owner's `options.<root>` module marks exactly the curated extension points and leaves the root node, `enable`, and global fields unmarked. For `attrsOf (submodule m)` the marker sits on the attrsOf option node and inherits to every dynamic child; an inner submodule option may re-mark `contributable = false` to punch an owner-only hole. Example nginx owner module: `options.nginx = { enable = mkOption { type = bool; default = false; }; package = mkOption {...}; virtualHosts = mkOption { type = attrsOf (submodule vhostModule); contributable = true; }; upstreams = mkOption { type = attrsOf (submodule upstreamModule); contributable = true; }; }`. Same for `postgresql.ensureDatabases` / curated `redis.*` keys.

OWNER METADATA (publish-time, owner side): the existing options-only eval that derives `declares` (module-system.md §"Provides — derived, not declared"; does not force `config`) is extended to descend the static option schema — including into `submodule` types via the `_submodule` modules already captured at lib/types.nix:564-573 — and emit, per declared option path, its `contributable` value. These populate the owner's per-package `OwnedRoot.contributable` set (attrsOf dynamic segments stored as a `*` wildcard, e.g. `nginx.virtualHosts.*.serverName`). Only paths whose declaration carries an EXPLICIT `contributable` value populate that field; intermediate paths inherit at check time. *(As originally specified this per-option `contributable` data was aggregated into a registry-wide provides map; that aggregation is superseded — see the 2026-07-21 amendment. It is now per-package metadata fed into `SystemRoots` at resolve time.)*

RESOLVER ENFORCEMENT (publish-time authorization pass, for package A):
1. Enumerate the config def-paths A authors (the AST write-scan already specified in module-system.md:78-81, or the leaf paths of A's `config` attrset). Each def's provenance is the resolver-stamped authenticated package identity (A's signed id at publish; the verified fetch source at resolve) — the SAME non-module attribute the engine reads at the priority-assignment step per M-forgeable-file (lib/modules.nix:695). Module-supplied `_file`/`file` (lib/modules.nix:669) is ignored here.
2. For each def-path D: let R = head(D); look up `owner = index.rootOwner(R)`.
   - If owner == A (A is the structural `{pkg}` owner of R, or the registered owner/provider of shared root R): ALLOW.
   - Else (foreign write): find Q = the longest path in `index.surface(owner)` that prefix-matches D (with `*` matching any one concrete attr name) AND carries an explicit `contributable` value. AUTHORIZE iff Q exists and `Q.contributable == true`. If no ancestor carries an explicit value, the path is owner-only → reject.
3. The owner need not be present in the resolved set at publish; the check reads the index only — no eval of A against the owner.
4. host.nix-provenance defs (operator, tier 75) bypass the check entirely. Foreign top-level `{service}.enable` is never contributable, so it is rejected here; the package instead emits a resolve-time assertion (`requires nginx.enable = true; set in host.nix`), collected at lib/modules.nix:935.

EXACT REJECTION RULE: Reject publish of package A iff there exists a config def-path D authored by A (provenance = A's authenticated identity) such that, with R = head(D) and owner = index.rootOwner(R): owner ≠ A AND there is no path Q in index.surface(owner) where Q prefix-matches D, Q carries an explicit `contributable` value, and that value is true. The diagnostic names A@ver, the full path D, owner@ver, and the owner's contributable surface, distinguishing "foreign root R not owned and exposes no contributable sub-path" from "<D> is an owner-only sub-path of shared root R (owner exposes [...])".

WORKED EXAMPLE (nextcloud → nginx): nginx@1.2 publishes surface `{ nginx.virtualHosts: contributable=true, nginx.upstreams: contributable=true }` (root `nginx`, `nginx.enable`, `nginx.package` carry no explicit flag → owner-only). nextcloud@7 authors two foreign defs:
- D1 = `nginx.virtualHosts."cloud.example".{serverName,locations,...}`. R=nginx, owner=nginx≠nextcloud → foreign. Longest explicitly-flagged prefix Q = `nginx.virtualHosts` (true) → ALLOW. Composition works without operator wiring.
- D2 = `nginx.enable = true`. R=nginx, foreign. No prefix in the surface carries an explicit contributable flag (neither `nginx` nor `nginx.enable` is marked) → REJECT: "nextcloud@7 may not write nginx.enable: owner-only path of shared root nginx (owner nginx@1.2); contributable surface is [virtualHosts.*, upstreams.*]. Declare a resolve-time assertion requiring nginx.enable = true (operator sets it in host.nix)." nextcloud's service stays un-started until the operator enables nginx at tier 75; conscription is blocked while vhost composition succeeds.

## rfc-0011-open-questions — RFC-0011 generations: retention, ABI locus, stateVersion, reboot orchestration, host.nix pinning

**Decision.** Lock all five open questions in generations.md §"Open questions": (1) Retention — keep ≥1 prior base-lib closure on /var via a dedicated per-image-gen GC root, independent of the ESP ×2 UKI slot count; never rely on re-download for cross-ABI re-eval. (2) Measured locus — write AOS_MODULE_ABI=K plus AOS_BASELIB_DIGEST into the UKI .osrel (os-release) section, which is already in systemd-stub's PCR-11 measurement set, and bind the actual base-lib bytes to PCR-11 via the dm-verity roothash on the measured .cmdline section (adopting known-issues F1-A). (3) stateVersion vs module_abi — keep them orthogonal; two distinct os-release fields gating different things at different times. No collapse. (4) Auto-reboot — first-boot re-eval service, NOT an apm-driven reboot-spanning two-phase transaction; apm stages the UKI + records pending intent, reboot per KernelUpgradeMode, an idempotent oneshot does steps 3-4 on the new image's first boot. (5) host.nix pinning — pin per config-gen by content (the host.nix store path recorded as host_nix_ref and GC-rooted by the existing per-gen cfgsrc/ root), not by a mutable git ref.

**Rationale.** Grounded in the worktree: ESP is sized ×2 (modules/image/_builder.nix:192-197) yielding only 2 UKI slots, while config-gens are cheap on /var (profile/mod.rs prune_generations keep-window) — so base-lib retention must be decoupled from ESP slots or cross-ABI rollback (generations.md "Different-ABI" re-eval rule, lines 122-126) silently breaks. The base-lib closure (option-schema lib) is small relative to a full UKI (kernel+initrd, ~100+ MiB), and the source image-gen may be unpublished, so retaining the lib on /var dominates re-download. For the ABI locus: aos-uki.nix assembles --os-release=@osRelease and --cmdline=@cmdline as PE sections, and systemd-stub measures .osrel and .cmdline into PCR-11 by default; os-release already carries AOS_STATE_VERSION and VERSION_ID (system.nix:248-258), so adding AOS_MODULE_ABI there gets the integer measured "for free" with no new section. But known-issues C1/F1 established that measuring only the integer claim was insufficient while the base-lib lived on an unprotected erofs root. The implemented F1-A resolution binds those bytes through the verity roothash on the measured `.cmdline` (`modules/security/verity.nix` and `systems/server-verity.nix`). stateVersion (system.nix:131, a string state-migration trigger run at activate) and module_abi (a monotonic int config-module admission gate run pre-eval, generations.md:154-177) gate different artifacts at different phases; a breaking option change need not migrate state and vice versa, so collapsing them would over-fire one gate. For reboot orchestration: activate.sh.in already re-runs the per-generation render at activate/first-boot time (the ignition fetch+files re-render, lines 183-208) and KernelUpgradeMode already has a Reboot variant (sysroot.rs:80-90); a cross-reboot two-phase transaction would need durable rollback state spanning a power event with no live process, while atomicity is already provided by sd-boot boot-counting (bad image → old slot/old config-gen live) and the ABI gate aborting before the /etc swap (bad re-eval → old config-gen live, the EX_PREPARE/EX_COMPOSE contract). For host.nix: the cfgsrc/ root already pins the host.nix store path per gen (operability.md:99-102, review M-gc-inputs), so a content pin is already the GC-rooted artifact; a git-ref pin would re-eval against drifted HEAD and defeat deterministic cache-hit re-eval.

**Mechanism.**

1. ## Safe NoCloud YAML and config-drive coverage (2026-08-04)

**Decision.** Parse only the NoCloud data contract AOS consumes, using the
safe in-tree parser, and reject unsupported syntax. Do not add a general YAML
implementation whose hermetic closure includes `unsafe-libyaml`. The three
offline labels (`aos-metadata`, `cidata`, and `config-2`) continue to use one
production `blkid -L` plus hardened read-only mount implementation. The
privileged fleet test exercises that implementation with a real labelled
ISO9660 device; deterministic probe tests exercise every label, priority, and
payload layout without repeating an equivalent privileged mount for every
label/filesystem pair.

**Rationale.** The metadata agent reads two narrow schemas: scalar fields from
NoCloud `meta-data`, and the v1/v2 network fields that become typed host facts.
A general YAML language is unnecessary attack surface in early boot and would
expand the bootstrap closure with unsafe code. Label selection is independent
of filesystem mounting after `blkid` resolves the device: all labels flow
through the same mount call and differ only in the selected parser. One real
mount test therefore proves the privileged mechanism, while per-label fake
probe and parser fixtures prove dispatch. This amendment supersedes the older
acceptance wording that required a vendored YAML crate and six nearly identical
privileged ISO9660/vfat mount cases.

**Acceptance.** The lock contains neither `serde_yaml` nor `unsafe-libyaml`;
malformed indentation, tabs, duplicate keys, and malformed flow values fail
closed; recorded NoCloud v1/v2 and OpenStack fixtures pass; the label table and
priority are pinned; and a fleet boot reads `user-data` from a real read-only
`aos-metadata` ISO through the production helper.

## F3-B index removal — enforcement moves to resolve-time SystemRoots (2026-07-21)

**Decision.** Remove the registry-published inverted index (`index/provides.json` / `ProvidesIndex`, schema `aos.provides-index/v1`) from the design entirely. Nothing registry-published replaces it. Shared-root ownership and capability-provider discovery become attributes of the **system** — the composed image/toplevel plus the installed set — not of the registry. This supersedes the index parts of F3-B above and the "registry-wide inverted index" mechanism referenced across the RFC.

> **Superseded text (historical, for provenance).** The prior design published, per registry, an aggregated **inverted index** at `index/provides.json` (`ProvidesIndex` with `IndexEntry` / `CapabilityProvider` rows: `option-path → {package@version, contributable}` plus `capability-token → setters`), rebuilt on every publish and fetched by the resolver, which queried it via `lookup(full_path)` / `providers_for_root(segment)`. Owned-root exclusivity and the F3-B foreign-write/conscription check were enforced **at publish** against this global index, and a shared root was gated at publish by a privileged system-extension key. **All of that is removed.** These names (`inverted index`, `provides.json`, `provides-index`, `OptionIndex`, `ProvidesIndex`, `IndexEntry`, `providers_for`, `CapabilityProvider`) survive in this entry only as the record of what was superseded.

**New normative model.**

1. **Private roots `{pkg}.*`** — ownership stays structural (root segment = package name). The resolver's missing-option lookup is a registry **by-name** metadata lookup (`registry.toml` → that package's `ConfigModuleMeta`, carrying `module_abi_compat` + `config_output`), ABI-gated pre-fetch. The error distinction is preserved: the name exists but its ABI band excludes the running `module_abi` K → `AbiMismatch`; the name is absent → `NoProvider`.

2. **Shared roots (`firewall.*`, `dns.*`, `nginx.*`)** — a locally-derived `SystemRoots` structure (`root → { package, version, interface_abi, contributable }`, plus a capability map `token → setters`) is built **at resolve time** from (a) the base-lib/image manifest's bundled roots and (b) the installed set's `ConfigModuleMeta.owns_roots` / `provides_capabilities`. It is computed on-host, never published, never fetched. A read/write against a shared root with no installed owner is a terminal, legible error (`"no installed package owns root 'firewall'"`) — the operator installs an owner; there is no auto-fetch of shared-root owners from the registry.

   Concrete variants use the same primitive: `nginx-full` and
   `nginx-minimal` each advertise `owns_roots = [ nginx ]`. That signed claim is
   their virtual-root `Provides`, and per-system owned-root exclusivity is the
   `Conflicts` rule. The operator selects one concrete package by name; the
   resolver does not choose an alternative in response to a missing shared
   root. This supersedes the earlier acceptance wording that requested
   `nginx.*` and expected registry-side alternative selection.

3. **Capability tokens** — setters are the union of the installed packages' `provides_capabilities`. An unmet token is a terminal resolve assertion; no auto-fetch. Any registry-side "install one of: …" suggestion is demoted to an optional, non-load-bearing hub search facility (future / non-normative).

4. **Invariants (restated under the new model).**
   - **Owned-root exclusivity is per-system**, enforced at resolve time (optionally early at install): two installed packages owning the same root is a hard error citing both. The registry never adjudicates ownership — two registry packages may both claim a root, but a system cannot install both. The privileged-registry-claim / system-extension-key-gates-a-shared-root-at-publish mechanism is deleted; trust moves to the operator's install decision (and install-time key policy).
   - **Shadowing guard.** An installed package's owned root colliding with a different installed package's NAME is a hard error (`SystemRoots` is consulted before the structural fallback).
   - **F3-B contributable enforcement moves fully to resolve time.** The resolver checks each installed contributor's `RootContribution.paths ⊆` the installed owner's `OwnedRoot.contributable`. Publish no longer performs the foreign-write/conscription check against a global index; publish-side lints that need only the package's OWN metadata may remain.
   - **Resolution algorithm.** Both missing-option cases (A: undeclared write, full path; B: absent-root read, first segment) collapse to root-based dispatch: `SystemRoots` hit → installed owner; else structural (root = package name) → registry by-name lookup; else `NoProvider`. Case A's full path is retained for error text only. The Case A/B classification detectors are unchanged.
   - **Fixpoint iteration cap** derives from the working/installed set size, not from index size.
