# Web route cutover ledger

This ledger is normative for the one-shot management Web UI cutover. A route
class marked **remove** is absent from both native and Worker routing after
cutover; it is not a redirect, alias, form fallback, or compatibility handler.

## Final route classes

| Route class | Methods | Final disposition |
| --- | --- | --- |
| Login, logout, magic link, OIDC, and passkey authentication | existing ceremony-specific GET/POST methods | retain server-rendered |
| Account password, passkeys, and session revocation | existing ceremony-specific GET/POST methods | retain server-rendered |
| Invitation and device-code activation | existing ceremony-specific GET/POST methods | retain server-rendered |
| `POST /-/auth/session-token` | POST | add session+CSRF to ephemeral bearer exchange |
| Public registry/package/release/channel/image browsing | GET/HEAD as currently specified | retain server-rendered |
| Public and authenticated immutable byte delivery | GET/HEAD with range support | retain shared native/Worker delivery path |
| Authenticated settings/management paths | GET | retain canonical URL as a client-application deep link |
| Authenticated settings/management paths | POST | remove; use canonical Connect API |
| Removed or renamed historical paths | any | remove without redirects or aliases |

## Canonical application roots

The following trees return the application shell for recognized GET deep
links. Their exact leaf inventory is generated by the application's route
registry and checked against the capability manifest.

```text
/-/instance/**
/-/orgs
/-/orgs/new
/-/org/{org}/**
/{registry}/-/settings/**
```

`/-/org/{org}/**` includes organization overview, projects, registries, binary
caches, storage bindings, domains, network boundaries, delivery endpoints,
storage gateways, topology defaults, IAM, SSO, signing keys, webhooks,
operations, audit, and danger workflows.

Registry settings include overview, access, placements, placement policies,
delivery, cache stacks, mirror, packages, releases, channels, images,
publication, signing, access tokens, configuration history, change requests,
operations, activity, and danger workflows.

Binary-cache settings include overview, access, placements, placement policies,
delivery, objects, closures, integrations, retention subscriptions, manual
roots, leases, population, coverage, garbage-collection policy/plans/runs/jobs,
signing, operations, activity, and danger workflows.

## Server-rendered exceptions

These route families never fall through to the application shell:

```text
/login
/logout
/auth/**
/activate
/-/account/**
/{registry}
/{registry}/-/packages/**
/{registry}/-/releases/**
/{registry}/-/channels/**
/{registry}/-/images/**
/_aos/**
```

Nested `{org}/{project...}/{registry}` public registry shapes receive the same
classification as flat registry slugs.

## Removed management transport

Every management form POST is removed, including plan, apply, create, update,
delete, credential, grant, route, placement, cache-stack, retention,
population, GC, signing-key, token, webhook, SSO, operation, and danger actions.
The application invokes the matching Connect methods and renders their typed
responses.

The following overloaded historical concepts remain forbidden in route names,
form actions, and handlers:

- `frontend` as a user-facing delivery resource;
- cache `link` or `unlink`;
- cache `pins`, `pin/add`, or `pin/remove`;
- a single `gc` POST that both plans and executes;
- a storage-binding pointer swap presented as moving a surface; and
- a combined serving/mirror mutation.

## Enforcement

Repository checks compare four inventories:

1. authenticated application GET routes;
2. retained server-rendered routes;
3. native and Worker mounted routes; and
4. API/CLI/Web capability mappings.

They fail when a management POST remains mounted, native and Worker differ, an
application deep link has no capability-backed workflow, a removed path is
rendered, or an unrecognized path receives the application shell. Retained
authentication and public routes are enumerated exceptions, not prefix-wide
fallbacks.

The executable negative inventories live in
`crates/aos-hub/tests/fixtures/removed-management-paths-v1.json` and
`removed-management-posts-v1.json`. The first contains concrete representatives
of every removed or renamed management route class and is tested with GET,
POST, PUT, PATCH, DELETE, and HEAD. The second contains every form POST mounted
by the final pre-cutover console, including POSTs whose path remains a canonical
GET deep link. Native router tests and the real `workerd` fixture consume the
same files, so the two runtimes cannot silently retain different compatibility
surfaces.
