# Normal Root startup prerequisite

The existing `aos-sandbox-policy-authorityd.service` now has a server-local,
nonauthorizing startup owner in the immutable enforcing profile. The legacy
and administrative CLI paths remain separate. This does not enable method46,
Source genesis client Intent/Floor construction, public Create, or FUSE reads.

The actual normal executable captures the entire inherited table before it
opens credentials, journals or listeners. PID1 delivers exactly two read-only
OpenFile roles: its original `/proc/1/exe` image and the selected image-built
`aos-normal-root-startup-profile-1/profile.json`. Names and environment select
slots only; neither is launcher or image authority. The original PID1 FD stays
in Root, never travels to the Controller, and is not a continuous proof of a
later manager reexec.

The profile producer reruns the existing attribute-expanded effective policy
checker on the selected final production binary. It joins that actual output
to the selected kernel's canonical readback provenance and resolves Root's
ELF interpreter and DT_NEEDED closure using the existing runtime-manifest
helpers and actual exportReferencesGraph. Exact file hashes and closure roots,
configured identities, and the final rendered normal unit are bounded inputs.
Only the single exact `OpenFile=<profile>:aos-normal-root-profile:read-only`
line is normalized to `@AOS_NORMAL_ROOT_PROFILE@`; every other unit byte is
committed. This explicit self-reference normalization avoids a build cycle,
not a hidden exclusion of authorizing configuration.

The owner retains and rechecks the actual original descriptors, own executed
inode and executable mappings, read-only current file names and contents,
genuine PID1 fixed-unit properties, exact nontransient fragment/invocation,
original self pidfd and kernel cgroup, empty capabilities/NNP, current normal
Root subject, and loaded canonical policy. Source-genesis stream phases borrow
and recheck that same local owner while the actual Root writer remains held.
The narrowly labelled public profile inputs have no file_type membership;
normal Root receives only read/open/getattr, its own exe symlink read/getattr,
and read/getattr on the already-owned init_exec_t PID1 image FD. No Controller
access to Root task files is added. Existing all-source custody cuts remain.

This local object cannot serialize or become a peer/read proof. A separate
Controller-side producer must still independently join the genuinely selected
immutable image and checked nondelegation matrix to the actual original Root
peer, fixed unit/invocation/cgroup and every live fragment. A Root self-report,
canonical-policy equality, supplied digest or path cannot replace that join.
FUSE also still needs the genuine Root-last current history/revocation,
Source floor, Cache, original Publisher, assignment/lease, two current content
grants and connected Mount/worker read barrier.

Qualification is pending: Rust compilation and authored regressions, actual
profile derivation/ELF resolution, final compiled policy queries, original
OpenFile delivery and physical labels/filesystem association, exact normal
unit/credential startup, property/invocation/image mutation negatives, and
installed process/cgroup/stream tests. Runtime dependencies, loader-cache and
future dlopen/environment behavior need actual fixed-image qualification;
DT_NEEDED resolution plus current maps is not an arbitrary future-load proof.
PID1 property readback is point-in-time, not administrative policy freeze.
Kernel/immutable boot/PID1 and deployed administrative custody remain the RFC
trust assumption. No Storage initializer or stage0 root-whitelist change is
part of this prerequisite.
