# Target ownership cutover

This cutover must preserve the existing whole-world fork transaction. Its acceptance
criteria include simultaneous sibling guests, descendant generations, exact
recovery and the original resource vectors. Compiling an unused constructor or
refusing a previously successful branch does not complete the cutover.

## Current implementation

The Target constructor retains its factory facade, Source checkout, selected
rows, partial native hosts, children and independent failures in the original
Main-prepaid allocation. Source construction now prices and prepares its reusable
selected storage before native Source effects. Scoped workers temporarily borrow
the same backend set; restoration occurs after joining and before parent-facing
reconciliation. Raw child-admission and scheduler-installation errors stay typed.

The actual Main constructor query uses the maximum of the Source and Target
constructor layouts. Target Service admission has its own fixed recipe in that
same Target role. Target physical return can discharge that Service without
writing a Source World-return journal. Neither recipe issues a Source grant.

The native factory now selects the owning transaction. It retains the genuine
factory facade, verifies the actual Source/Main binding, and installs Target
before RAM preflight, directory provisioning, workers or child birth. The old
native permit-only adapter is removed. Component tests keep their explicit
fixture backend and do not enter the native issuer. QEMU host test targets compile, and its
library has 1,147 passing tests with four ignored probes on this integration.
Those controls do not establish native VM activation or performance parity.

The joined constructor now publishes its complete assembly in place and retains
partial scheduler adoptions in the same Main body. Publication refuses without
allocating an owning error wrapper. During adoption, an exact generation and its
child remain in dedicated constructor slots until process authentication succeeds.
The API carrier receives partial adoptions before pre-body cleanup. Unadopted
children and returned adoption leases are drained in separate bounded passes;
their partition must still cover the original expected roster exactly.

The API builder now has a borrowed-carrier entry point shared with its ordinary
owning wrapper. Target installation stages its actual launcher, continuation and
adoptions in that original carrier before validation or construction IO. Its final
export reserves the original body-return destination and moves only the completed
Loop. The Source query includes the actual overlapping Target launcher headers,
adoption vector and leases, and reconciliation roster. This remains a single-family
construction measurement, not independently funded simultaneous sibling support.

The runtime owns an operation-only Loop view and the counted retirement observer
reserved before export. Its destructor returns the real body to Main. Shutdown
records its completed physical work before fallible metadata handoff; subsequent
publication records one immutable durable disposition. Main destroys the returned
body before saved Target cleanup settles that disposition and returns native loans.
Terminal metadata handback returns the exact original checkout; Source supervision
is restored outside pure terminal projections before provider reuse. Construction
and cleanup failures report by borrowing their original protected Main histories.

Promoted children retain their original return pair and a bounded-step lineage
controller. Descendant retirement keeps each parent checkout until exclusive
ownership permits the next ancestor handoff. These runtime paths compile but do
not yet qualify promoted-parent admission or the native multi-family issuer.
The default and private daemon library configurations have compiled on this
cutover. The private daemon library and test targets also compile after migrating
the comparison Service callers. They preclaim a genuine Target, start its Service,
and launch from that same move-only selection. The eventual child Context supplies
native supervision; the Source retains its original physical charge. Comparison
fixtures acknowledge their Context aliases before VM retirement and verify the
actual Main completion journal afterward. Preparation remains part of measured
launch cost.

The daemon runtime suite now reaches a complete result. File-only cleanup
fixtures use the real body/control primitive, return their actual report pins,
and preserve missing-role refusal in the native driver. Observation-publication
reconciliation passes on the ordinary test stack after separating fixture setup
from execution. Semantic fresh-request validation precedes Main selection and
runs once on each launch path.

Full-suite qualification still fails under descriptor pressure: the test process
inherits a 1,024-descriptor limit, and accumulated retained fixture resources
cause open-file refusals in later tests. Isolated whole-world atomicity, member
resource cleanup and the full 512 MiB unique-page RAM/GC vector pass. Those
isolated results do not waive the full-suite failures. A complete serial daemon
run at the ownership checkpoint also passes within the original limits; the
combined parallel run still exhausts descriptors. Deployed genuine-Main flights,
simultaneous native families, promoted-parent admission and performance parity
also remain outstanding.

A dropped Target terminal now attempts the same metadata handback used by an
observed terminal. If the parent is temporarily unavailable, it returns the
original constructor, reports and released Service tail to the same Main header.
The existing terminal-ready pass retries disposal; no replacement allocation,
native cleanup entry or new resource reservation is introduced. The original
report pin is returned without marking terminal disposal, so the role stays
occupied. A callback panic or poisoned metadata retains the actual payload and
refuses further disposal. New reports cannot enroll during outside terminal
ownership or disposal.

Unissued field/pin controls verify repeated return of the same Box and real file,
preserved raw errors, stale-epoch refusal, panic retention, poisoned metadata and
late-report rejection. These controls establish neither native Main return nor
the deployed parent/child handback path. Source Pending cleanup first refuses
while either original row allocation is lent. Only after those rows return can
its cleanup succeed and the driver latch `body_closed` or extract its post-body
obligations. The parent projection's closed-body guards agree with that ordering;
external Loop destruction alone does not close the prepared metadata destination.
Retiring-parent contention still needs end-to-end coverage.

Native comparison fixtures must retain the campaign's actual published Main
provider and its concrete factory recipe. Opening an independent raw allocator
does not supply that provider. Source and Target must also agree on the typed
row storage they exchange; a cast cannot establish either ownership or payment.
This integration remains unfinished. Cleanup error folding must also retain a
later independent Main report as well as the guard leaves covered by the
existing two-body component controls.

## RAM controller fork admission

RAM fork preparation closes the controller's policy admission before checking
cold handoff readiness, canceling queued placement, or quiescing and joining the
native control actor. An applying or unapplied policy, retained checkpoint, or
existing fork refuses before those preparation effects. The State mutex is
released before cancellation and native calls, so their original operations can
still observe supervision. A later preparation failure retains the closed gate
and its original error; it does not claim successful parent rearm.

This ordering repair does not supply the remaining native handoffs. The RAM
controller still requires genuine parent rearm, child controller construction,
child endpoint custody, and inherited endpoint close custody. Callback-child
reconstruction separately requires a fresh child startup Source. Those paths
remain explicit refusals. Local admission controls issue none of these native
owners and do not qualify a successful cold fork or promoted parent.

## Factory and runtime integration

1. Use `retain_fork_target_factory` to retain the real shared factory facade.
   This clones its existing host allocation, not a native allowance or another
   bank. The containing worker keeps its original facade; the Target constructor
   pays the retained facade's inline extent. A missing producer remains a real
   admission refusal.
2. Bind the genuine Source checkout and original Main selector before Target
   permit, directory, RAM, worker or process effects. Install every issued
   Ready/Retained outcome in its canonical row before reporting its status.
3. Keep complete assembly, adoption inputs and partial API construction in the
   same owner through every fallible step. A public error borrows that owner's
   actual causes. It must not replace an owning failure with formatted text or
   allocate a late replacement carrier.
4. Export only the runnable Loop. The Target constructor retains its aggregate,
   exact native loans and Source checkout. Actual Loop return and destruction
   precede aggregate/native release; historical errors remain independent of
   successful physical return. Use the existing Main carrier and destination.
5. Return Source metadata only after its Target-owned contents and reports are
   disposed under their payer. Restore the exact checkout through its provider;
   no Arc count, absent field, stale epoch or successful post substitutes for a
   native return journal. Preserve direct-source and descendant-lineage recovery.

## Simultaneous children and promoted parents

The current same-family native issuer has one Target slot, occupied through
actual child retirement. Lending a single persistent Source-paid row allocation
for that same lifetime would also serialize live children. Neither restriction
can satisfy the existing 1, 2, 4, 8 and 16 live-sibling comparisons.

An independently admitted child must use its existing Service/Execution funding
and genuine Main/native issuer. Its persistent launch rows, mutable private RAM,
backing growth and native controls need that independent payer before birth.
The Source retains its immutable basis and real borrow obligations. Source-paid
scratch may be borrowed during construction and returned after workers join; it
cannot become an unpriced per-child persistent allocation. Do not increase a
ceiling, reuse an occupied Source epoch, mint a Source role solely to stand in
for a Target, or claim that Source never started to release a Target.

A promoted child must remain a valid retained parent for later generations.
Parent eligibility must come from its actual stopped/template state and native
process binding. Its original birth as a Target must not silently disable
nested forks, and its containing Main/native return obligations must remain
intact through promotion. Complete this together with the independent-family
issuer rather than treating the first single-family increment as qualification.

## Qualification

Keep the original comparison predicates, resource vectors and live-child counts.
If moving admission or checkout relative to the ready-time timer, include that
work in the corresponding measured cost; moving it outside the timer is not a
performance improvement. Requested worker stack bytes are only part of the host
peak: private thread/TLS/guard/control allocations still need their actual payer.

Native fork/reconstruction samples stay in the original selected launch rows.
The live runtime projects total and maximum duration only after every live row
has both a sample and a completed adoption. Missing, overflowed or stale samples
cannot establish performance evidence. The overall ready timer still includes
admission, staging and checkout; no post-launch sample vector is allocated.

Run component controls, complete default/private test-target compilation and
local runtime suites, then the installed genuine-Main native flights. A Cargo
test executable does not become Main through an in-process fixture. Qualify RAM
identity, isolation, lazy paging, descendant recovery and wall-clock/CPU parity
on real guests before claiming completion. Keep the final current-source
packaged all-application test-target build and required boundary gates.
