# Public vendor integration and behavioral acceptance

The portable vendor boundary is CNP/1, specified by RFC-0025 chapter 06.
Native Rust traits are a host implementation technique, not the vendor ABI.
A third-party process can use the public framing, envelope, negotiation, schema,
blob and original-request journal components in `crucible-node-provider`, or
implement the same wire grammar in another language.

The common host path is already public. An installed broker can implement
`SimulationNode` and `NodeProvider`, supply actual inactive native resources to
`PreparedRealization`, and use `admit_graph` plus `NodeRuntime`. The graph gate
requires trusted implementation measurement, live authority, schema support,
exact selected qualification, complete ownership and connection evidence.
The runtime separately requires actual preparation/readiness, complete durable
world activation and opaque original grants. Transport decoding and a provider
claim cannot create these authorities.

The supplied owning CNP adapter currently translates the measured quantized
checksum companion profile through `CnpReferencePreparation` and
`CnpReferenceNode`. It retains an actual Child, private process group, controller
originals, input/operation journals and source-qualified native receipts.
It is not a generic Compute, Clock or arbitrary-device adapter. In particular,
the framework does not yet provide a generic CNP-to-common-node translator for
every advertised timing/state/role facet or arbitrary external hardware custody.
A vendor using another semantic profile currently needs an independently
installed host translator implementing the public common interfaces.

## Acceptance at actual CNP admission

`CnpAcceptedPreparation::prepare` adds a required host-installed
`CnpRealizationAcceptance` gate after genuine native realization authentication
and before the original CNP `Admit`. Its opaque capsule exposes immutable
descriptor/binding/owner observations; it offers no unchecked conversion into
the legacy preparation capsule. `into_node` reauthenticates current native
custody and behavioral acceptance before common node construction. Failure
retains original resources in the existing finite supervisor slot.

The borrowed `CnpAcceptanceScope` supplies the actual retained launch guard,
original closed-gate record and original Realize resource limits alongside the
profile, response and node/owner bindings. These observations let an installed
host policy authenticate current native environment scope; none are new wire
claims or admission permissions.

The daemon's `CnpBehavioralAcceptance` implements that gate using the complete
original acceptance record and independent installed evidence policy. Its
projection binds source implementation artifacts, selected configuration,
owner geometry, original Realize resource limits, original descriptors,
timing/capability/guarantee contracts and role/port profiles. It derives all
required classes from those actual
contracts, rather than accepting a vendor-submitted class subset. Independent
policy supplies freshly measured environment, harness and fixture identities.
Each source projection is counted under a 256 KiB serialization ceiling before
allocating canonical JSON; original claims and retained acceptance records keep
their existing separate ceilings.

The same original acceptance verifier is used by `BehavioralAdmissionEvidence`
at whole-graph admission. Every call checks the exact binding and original
claim, reopens current scope once, and reauthenticates complete original evidence.
A historical Accepted record, successful parser or self-reported Passed case
cannot bypass the current oracle, coverage catalog, prerequisites or required
realized-provider cases. Native source qualification remains independently
mandatory; this acceptance layer cannot replace it.

The old closed-reference preparation route and its wire bytes remain unchanged.
It represents its existing independently source-qualified limited profile, not
a general vendor behavioral acceptance exemption. General/vendor brokers must
install an independent complete policy before claiming mandatory classes.
No CLI selector is required for the reusable public host interfaces, but the
ordinary installed catalog currently exposes only source-owned closed profiles.

## Qualification and remaining work

The added native fixture tests actual process ordering, refusal custody and
fresh checks without redispatch. The synthetic acceptance fixtures test changed
source/configuration/harness, reduced classes, missing originals, model-only
success and finite projection limits. These tests do not qualify a new vendor,
CPU, device, capture class or arbitrary CNP broker.

Full third-party acceptance still requires independent realized-provider
evidence for the claimed class/configuration and complete applicable normative
coverage (CN-TEST-001 through 009 and 033/034). The framework's protocol-only
conformance runner keeps its original schema and meaning. A generic owning CNP
translator, source-qualified native receipt validators for its supported facets,
and complete independent vendor class witnesses remain required for profiles
beyond the supplied checksum process adapter.
