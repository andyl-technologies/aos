# Shared native gem5 model qualification

The native controller owns private transport, exact callback stops, operation
custody, diagnostic credit, process-image capture, and restored control routing.
A source-owned model implements realization, native publication inventory,
original publication acknowledgment, private resource rebinding, and its closed
scope description. The existing production SE controller remains unchanged
while the successor's host codec and continuation format are implemented.

## Current evidence

The isolated ARM model uses the installed Linux kernel, initramfs, bootloader,
and board configuration, a VExpress GEM5 V2 board, 256 MiB of RAM, a 100 MHz
Atomic CPU of width 16, and a native tick of one picosecond. It does not claim
CPU timing fidelity. The three guest asset roles and the complete Python board
configuration tree are measured before native model allocation. Listener
creation is disabled; the exposed serial facet records actual PL011 callback
births and retains every original byte until its original acknowledgment.

The host witness captured the first held Linux serial byte at tick 1166530000,
native callback ordinal 116654, and tick ordinal one. It archived bounded,
independently copied primary and supplementary image files and the complete
private resources, then removed the entire original image/resource/temporary
namespace before reconstructing two concurrent owners. Each owner:

- authenticated its supervised kernel peer, original native executable mapping,
  reconstruction executable, and native resource helper;
- recovered the same original held receipt and unchanged exact callback cut;
- captured a new image in its own private image namespace and passed an
  independent audit of captured map, thread, descriptor, file-map, image-body,
  and immutable model-asset custody;
- acknowledged the original held publication and produced the same eight
  subsequent original UART receipts, including their birth positions;
- terminated with a waited leader and a complete empty process-group census.

The historical primary image remained unchanged. Nineteen adversarial asset
policy tests reject altered scope, qualification claims, bindings, extents,
mapping rights, private file custody, and transformed mapping geometry. Linux
can merge DMTCP's temporary file placeholder with an adjacent private guard.
The audit reconstructs only the exact native-attested file subinterval for
current custody checks; the guard retains anonymous custody, and the entire
original placeholder remains bound to its captured image bytes and protection.
Overlapping transforms, partial or ambiguous coverage, and external or writable
placeholders refuse admission. Seven custody tests exercise finite
preflight before destination allocation, changed source detection, symlinks,
shared inodes, and independent private copies. These are mechanism checks;
they do not qualify public execution authority, complete device parity, guest
readiness, or CPU timing. Partial modeled diagnostics remain partial even when
the native process image has complete audited byte custody.

The source-owned check package is `gem5-shared-controller-arm-check`. It reruns
these checks using its exact installed native and source-built guest/tool
dependencies and retains the matching helper and recipe sources. The helper
scope is fixed by those sources. Hashes supplied by a caller do not create
profile admission.

The installed `gem5-arm-model-profile` mechanism bundle measures 31 exact native,
controller, model, auditor, reconstruction, guest, witness, and source roles,
including the additive Terminal inventory patch and its recipe. It remeasures
the complete configuration tree using the same sorted path/extent/hash codec
as the native model, and checks the witness's source/helper and guest bindings.
Its host image ABI is fixed to Linux/x86_64, little endian, 64-bit pointers,
4096-byte pages, and the source-built DMTCP 4.2.0 image format. The ARM guest
architecture is independent of this host process ABI.

Fourteen adversarial writer tests cover absent original/fresh gates, capability
overclaims, malformed native birth scalars, wrong serial facets, symbolic or
shared file aliases, finite preflight, changed source recipes/helpers/native
extensions, and changed complete configuration census. This metadata package
consumes the actual source-built shared-controller proof; it does not substitute
metadata parsing for native capture. All execution, full-system, device parity,
readiness, and CPU timing admission fields remain false.

An isolated Rust draft uses a compile-time source-installed manifest binding,
remeasures artifact bytes and extents independently, and refuses execution
admission. Its model-aware readiness and continuation records select the ARM
dialect explicitly, retain original serial births and successful/refused prefix
custody, and reject changed model/profile, duplicate operations, fabricated ACKs,
and impossible callback progress. These records remain inert until the live
native driver and common-node consumers enforce the qualification conjunction
below; the production native/2 source and installed policy remain unchanged.

## Minimum exact-preservation qualification

Exact preservation is a separate capability from deterministic realization,
guest readiness, device support, and CPU timing fidelity. The production
opaque-image certificate must require the following complete conjunction:

1. **Source-owned installed profile.** Its trusted manifest binds the exact
   native executable and patch closure, shared controller, fixed model,
   auditors, capture/reconstruction/resource-helper tools, host ABI, board and
   CPU parameters, one-picosecond native clock, finite superdense mapping,
   kernel/initramfs/firmware/configuration assets, and allowed external facets.
   The compiled installed verifier selects this policy; scenario hashes or
   operator paths cannot install it.
2. **Authentic parked capture.** The supervised live PID, start ticks, process
   group, source configuration, original capture ID, and exact logical/native
   boundary match the sealed image. Native event service does not advance or
   drain between the cut, held publication receipt, and capture.
3. **Complete native process closure.** Every task context and kernel mapping
   is accounted for by the image and native captured ledgers. Immutable code
   and shared read-only guest-asset mappings have independently measured
   custody. Every descriptor is a modeled private resource, classified native
   checkpoint machinery, or a closed operational route. Unclassified shared
   RAM, devices, sockets, workers, or host-derived guest inputs refuse admission.
4. **Complete controller custody.** The image retains exact original requests,
   successful prefixes, outstanding/refused polls, diagnostic objects, original
   publication FIFO, acknowledgment state, deferred native callbacks, and
   superdense counters. Operational socket, resource, supplementary-image, and
   temporary routes rebind without changing modeled state. A failed subordinate
   poll never erases earlier progress or becomes a successful horizon receipt.
5. **Portable fresh reconstruction.** The signed complete artifact roster is
   privately materialized after the original namespace is gone. Two independent
   current owners prove unchanged held receipts, fresh capture closure,
   continuation and original acknowledgment behavior, and complete group
   reclamation. Each current owner obtains its own live certificate; it cannot
   reuse its source owner's certificate.

An installed profile can advertise exact preservation after that conjunction
is enforced by the production native driver, installed verifier, common-node
adapter, and signed continuation format. The mechanism helper's current false
admission flags must not be changed into authority without these consumers.

## Production integration order

1. Land the shared native loop and typed diagnostic refusal protocol with an
   explicitly installed dialect. Retain compatibility for production native/2.
   Select `SE native/3` or `arm-linux-native/1` from trusted model policy before
   bootstrap. Parse serial publication records separately from SE stdout
   records: UART receipts have a terminal/facet and no guest PID or file
   descriptor. Preserve native output IDs and all birth ordinals.
2. Replace SE-specific launch assumptions with a typed finite asset closure.
   The fixed ARM profile includes the kernel, initramfs, firmware, configuration
   tree, generated DTB, controller/model helpers, and all captured private
   output resources. Introduce a source-owned ARM profile package and installed
   verifier instead of widening the existing fixed ELF allowlist.
3. Generalize opaque certificate issuance over trusted closed model policies.
   Keep its authentic peer/source/image/boundary checks and complete native
   ledger audit. Separate `byte_closure_complete` from modeled diagnostic
   coverage; reject absent resource domains or transport uncertainty. Seal the
   selected model/profile and auditor into the exact source identity.
4. Extend the backend-keyed continuation edition with model asset bindings,
   selected dialect, serial receipts, successful/refused prefix custody, and
   supplementary-file source-root lineage. The generic `PreparedOwner` and
   `NativeArchive` path must enforce the installed verifier and exact resource
   roster before any modeled callback or output publication.
5. Run an actual common-node scenario that captures a held ARM serial output,
   removes its original namespace, reconstructs two fresh worlds, independently
   recertifies their live native cuts, publishes and acknowledges the original
   output, and compares native continuation. Negative cases cover changed model
   assets, wrong backend/profile, cross-owner receipt reuse, missing resources,
   refusal custody, altered native birth, and early child exit.
6. Qualify network, block and 9p separately through real Linux guest workloads
   and the same native coordinator input/output custody. Existing functional
   driver probes and finite native VirtIO tests are useful prerequisites;
   complete device parity requires the actual common-node surface and signed
   restored ledgers. Repeat source-gone two-world tests with device requests or
   replies held across capture. A successful early UART continuation does not
   establish any of these device capabilities.

The ARM RTC's pinned board default is 01/01/2009 and its counter advances from
native simulated ticks. The source-owned profile must audit that default and
the disabled listener paths explicitly rather than infer absence of host input
from a short console sample. Other full-system devices and future external
nodes require equally explicit supported resource and input policies.
