# Installed public reference-provider adapter

The public reference provider and its controlled checksum companion remain
separate owned processes. The controller authenticates the actual Unix peer
PID and UID, independently measures its executable through the native process
handle, and admits the closed Hello exchange through the trusted installation
verifier. A vendor-supplied manifest, receipt reference, or successful blob
transfer does not establish native execution authority.

## Dynamic control evidence

The distinct public byte-linked profile advertises `cnp.control-evidence/1`.
The original public checksum profile retains its existing advertisement and
traffic. A controller selecting the new behavior must negotiate this feature
before realization. The feature uses the baseline provider-origin
`BlobBegin`, `BlobChunk`, and `BlobFinish` methods; it does not add a content
lookup method.

After a completed Realize, Activate, Input, WorldActivate, Begin, Poll,
Observe, QuantumClose, Abort, or Release response, the provider transfers all
new locally retained content referenced by that response. It traverses
canonical JSON records and sends dependencies before their referring objects.
It omits exact profile content and private bootstrap objects already owned by
the admitting controller. Independently measured executable artifacts are
also omitted. All other missing or mismatched local references refuse the
transfer. A digest cannot acquire a different length, media type, or hash domain.

The closure is bounded by 4096 objects, 64 dependency levels, the source
provider's installed content-byte ceiling, and the negotiated frame, nesting,
chunk, correlation and original-request journal ceilings. Transfers retain
original request IDs and fixed chunk cuts across authenticated same-incarnation
reconnects. A finished transfer proves immutable byte custody only. Output
publication and semantic input consumption retain their independent original
owner receipts and journal obligations.

With this feature selected, these response-derived closures replace the
legacy observation-window's additional implicit content transfers. Therefore
the controller can finish receiving every response root without leaving an
unannounced tail of transfers ahead of its next command. The original profile's
observation transfer order remains unchanged.

## Controller custody and time bounds

The client records the original controller request before publishing it.
Connection sequence is the only field refreshed on a replacement stream.
Changed original material refuses locally; a received outcome remains associated
with its original request. Accepted responses release transport correlation
credit without releasing original operation custody. EOF or partial writes
leave originals under the mandatory supervisor rather than allocate substitutes.

Client content has independent finite byte, object, chunk and transfer-identity
ceilings. A complete advertised length is reserved before chunks are accepted.
Chunks are contiguous or exactly match their retained original range. Finish
checks complete bytes against the original ContentRef before acknowledging
custody. Completed content and retry ledgers share one immutable allocation.

Host monotonic time bounds blocking transport only. All clones share one
absolute exchange deadline; byte progress never renews it. Receiving a response
and then its promised evidence tightens the original deadline instead of
starting another budget. This operational cutoff never supplies modeled time,
event ordering, execution progress, persisted state or determinism guarantees.

## Private installed qualification binding

The explicit private launch edition three binds the public byte-linked profile
to nonempty host-selected qualification references. It carries every referenced
object's exact bytes in private installed content, requires canonical unique
reference order, and limits the roster to 4096 objects. The host admission record,
public realization, controller and node adapter commit to the same qualified node
and owner binding identities before graph admission. The original raw bootstrap
and edition-two public fixtures retain their original empty qualification roster.

`ReferenceProfile::bind_qualified` and the private bootstrap helper construct
data; neither accepts evidence or issues a qualification certificate. The trusted
host installation registry independently authenticates scope, measured source,
actual native ownership and guarantees. Public vendor receipts and byte-transfer
acknowledgments cannot satisfy that registry or weaken whole-graph admission.

## Evidence scope

`tests/client_reference.rs` launches the actual source-built public provider
and companion through private edition-two and installed edition-three bootstraps. It
authenticates measured peer identity, receives the full native gate receipt
closure, checks original receipt and owner scope, verifies the real companion's
kernel parent relationship, distinguishes unchanged and changed original
requests, and confirms companion disappearance after native abort and reap.
The installed case additionally checks that the complete realization and actual
host admission retain the exact original qualification-bearing binding hashes.

The core adapter's explicit actual-provider preparation case also verifies
qualified discovery, realization and admission through the measured public
endpoint. It authenticates native readiness, checks an unchanged retry and a
changed-world refusal, and confirms that readiness alone leaves the world gate
closed. The test retains the original handshake registrar with the controller,
provider child, companion and host journals in the pre-reserved supervision
capsule, then checks actual companion and provider reclamation.

The core two-provider world case independently launches a closed-ingress source
and an admitted-ingress consumer, preserving both public profile bindings. It
admits their complete graph, authenticates both original native readies,
extracts the full initial coordinator, and commits a complete publication
through an owning test publisher. Genuine source output crosses the admitted
connection unchanged; the consumer's result must match a separately calculated
checksum over the exact original octets. The test checks original provider event
IDs and native FIFO values separately from coordinator delivery sequences.

Both actual children are then reclaimed beneath the original whole-world
capsule. That capsule retains the complete activation, preparation, coordinator,
operation and input journals until explicit release; only afterward are the
original leaf journals transferred to their pre-reserved process supervision
slots. The test confirms both companion PIDs disappear.

These checks establish local public protocol, genuine native preparation,
complete in-memory world publication, connected byte delivery, and retained
resource behavior. They do not qualify exact execution, preservation,
deterministic replay, physical pause, CPU fidelity, or a generic third-party
provider. Installed factory selection and complete durable publication/restart
remain separate integration obligations.

## Initial coordinator publication

`NodeRuntime::initial_coordinator_snapshot` encodes the
`crucible/coordinator-initial/1` object after complete native arm. Every node must
positively authenticate its fresh initial realization through
`validate_initial_preparation`; the default refuses. Empty represented host
ledgers cannot establish fresh state for a restored node awaiting continuation
installation. The installed CNP adapter has no restore constructor and checks
its original measured realization, unchanged ready receipt, zero boundary,
parked application, initial input sequence, zero checksum and absent activation,
input and operation custody.

The bounded canonical object contains the actual activation, full world binding,
all original native readies and prepared owner records, complete node descriptors
and live bindings, routes, owner incarnations/domains/conflicts, selected execution
and port/connection policies, ownership and coordinator policies, scenario
requirements and runtime limits. Its scheduler is explicitly not initialized;
operation, input, publication, delivery and reservation ledgers are empty only
under the preceding native proof. Native handles, sockets and process-local
thread identities remain in supervised custody. The object records thread
custody policy rather than turning host thread identifiers into portable authority.

This object is input to the trusted complete durable activation publisher. It
is neither an activation permission nor a restore image. A public `WorldActivate`
uses only the original owner preparations and complete coordinator bytes retained
in the runtime's committed opaque `WorldActivation`. A scalar activation record
cannot stand in for this coordinator state.

## Uncertain input and original public identities

Before activation, blob upload or `Input`, the adapter reserves the exact opaque
host input batch, public event batch, immutable payload bytes, original cut and
batch sequence in its supervised ledger. The acknowledgement remains absent
until the complete original receipt and pending inventory validate. Any failure
leaves that original input unresolved; an unchanged retry refuses to resubmit,
and a changed retry cannot replace the original or allocate another sequence.
Dropping the borrower transfers this ledger with its actual child and controller
into the already reserved supervision slot.

Output identities and provider source FIFO values are retained unchanged.
Producer-local event IDs can coincide across different producers; the source
provider returns a unique acceptance ID set, while the complete input batch hash
and pending inventory bind every event and payload. The host scheduler maintains
its own delivery sequence independently. CNP input events carry the separately
retained original native source sequence; coordinator consumption prefixes keep
their original coordinator identities. Position-only causal parent metadata
currently refuses at the CNP input boundary: a subsequent hop requires an
installed mapping to actual original parent event IDs. This limitation must not
be hidden by assigning fabricated IDs or rewriting original outputs.

## Original input provenance

Nonempty CNP input requires the runtime's opaque `InputProvenanceClosure` for
the same original world, consumer, staging operation, batch and inventory. The
sidecar carries the authenticated producer's original proof bodies separately
from modeled payloads. The consumer retains this sidecar before remote effects
and uploads its complete immutable objects before issuing `Input`; it does not
insert proof bytes into the guest's input or reconstruct producer receipts.

The adapter's finite boundary registry retains original public receipt bodies
and their known codec dependencies only after semantic and native checks. Its
producer callback returns the complete transitive dependency inventory. Foreign
proof bodies received through the opaque sidecar remain original immutable
bytes, but the present sidecar does not declare per-object dependency edges.
Querying such an inherited non-leaf codec therefore refuses rather than treating
it as a dependency-free leaf. The authentic generic checksum window receipt
declares a leaf and supports the initial direct producer-to-consumer proof path.
The actual two-provider core case exercises that direct connected path. Further
hops requiring original parent IDs or inherited non-leaf dependency declarations
remain refused until their installed mappings are available.
