# Fixed ARM Linux device foundation

This private successor owns a closed ARM Linux boot monitor and two real modern
VirtIO MMIO transports. The board-owned slots remain 0x1c130000 (network) and
0x1c140000 (block), with the original IRQ, DT generation and bus connections.
It does not replace the known-ELF SE or parent0 UART profile.

The existing source-built block regression emitted 19,194 UART bytes, serviced
13,300,000 native callbacks and verified five read/write/flush requests at native
tick 870799820000. A per-byte control prefix cannot retain that boot within the
old finite diagnostic and receipt budgets. This successor therefore has no
external serial input or publication route: every actual native UART FIFO birth
and byte remains in the machine, and its complete bounded row table is included
in each original immutable partial diagnostic object. It does not synthesize a
coordinator publication for those earlier bytes.

The selected partial observation includes native queued events/RNG, the two
actual device visitors, and the original closed terminal FIFO. CPU registers,
pipeline, RAM bytes, caches, unselected device fields and polymorphic inherited
payloads remain omitted and explicitly incomplete. Whole opaque image closure
is a separate actual map/thread/FD/source/asset audit. The model keeps the fixed
4 MiB per-object reservation and existing 256 MiB cumulative diagnostic limit;
no original observation is discarded. Every device input has a closed original
request, retained reply, finite operation and byte census, native future tick,
and causal parent. Repeated original requests return the original receipt.

The first native witness must stop with an actual Linux block read held and an
original future reply sealed. It captures the complete process without drain,
independently audits it, removes the entire source images/resources namespace,
and reconstructs two concurrently owned private copies. Each fresh child must
recapture and obtain its own complete byte-closure audit before the exact held
request/future reply is replayed. The original native completion birth and every
prior UART FIFO row must match the baseline. Anchored group custody, one reap,
and complete finite helper census are reused from the reviewed Root helper.

This is device foundation evidence. Common Ready, external serial causality,
ordinary NativeArchive, full device parity and CPU timing remain unqualified.
A production Linux lifecycle needs either a typed closed boot/preparation phase
or durable original diagnostic/receipt transfer and versioned retirement. That
contract must retain all original bodies and distinguish already progressed
windows from a later zero-effect Poll refusal.

stage. The source-built ALL compiler/queue mechanism and actual first Linux

# Closed application block lifecycle mechanism

This source-selected functional profile preserves a fixed 1 MiB zero-initialized
in-process disk and all original finite native block commands. It is distinct
from the immutable first-kernel-read foundation and from Root/SE implementations.
The common controller bytes and predecessor board realization remain unchanged.

The new native extension binds one private retained source-owned Event handler
before callbacks. A request invokes that handler synchronously inside its actual
native birth callback. The handler retains the immutable command and schedules
its owned managed PyEvent at a fixed future native tick. A default-off native
publication-stop policy returns only after the whole birth/completion callback,
so the command, future reaction and guest-visible queue state can be captured
together without draining. The handler is not itself a queued extra reaction.
Public process frames contain no native pointer or callback table.

The new completion inventory exposes actual status and descriptor head as
separate fields. The predecessor getter is unchanged: its fifth element is a
descriptor head, despite the predecessor first-head-zero/status-zero diagnostic
label. This profile never interprets that getter as a status authority. The
native primitive witness deliberately exercises status 2 and head 0, and the
closed lifecycle requires successful status independently of the native head.

At the fixed future backend reaction, a read snapshots the owned disk bytes,
a write commits the original guest payload, and flush is an explicitly ordered
no-op. The frontend completion is scheduled one native tick later. Managed event
objects, original commands, disk backing, replies, completion bodies and original
ACK coordinates remain inside the opaque process image. The Python model retains
all these objects; no host disk, thread, input socket or external reply driver
supplies hidden state. New device control inputs are refused.

The command ledger admits 128 original operations, 4,096-byte payloads and one
fixed 1 MiB disk. Native frontend capacity remains sixteen. Before each bounded
native batch the model reserves sixteen possible new originals and the inherited
publication/terminal credit. A request/completion birth immediately ends that
native batch; no later callback consumes an unreserved new command credit. Original
completed commands are never discarded. Callback/time, terminal, diagnostic
object and cumulative custody limits remain 16 million/1e12 ps, 32,768 rows,
4 MiB and 256 MiB respectively. An overflow is failed/uncertain work, never a
fabricated NoEffects result or a broader successful horizon.

The diagnostic projection is explicitly partial. It adds at most 64 KiB of
owned disk/event metadata to the inherited structurally bounded projection
(4,034,560 bytes), remaining below the existing 4 MiB object ceiling. It commits
raw disk and original payload/reply bytes and lists pending managed events, but
does not claim complete CPU/RAM/cache, native callback or Python object visitors.
Exact opaque map/task/FD/assets/image auditing preserves hidden machine bytes
independently of those typed diagnostics.

The actual acceptance gate requires the source-built application INIT_READY,
the original 4 KiB page-cache write containing the 512-byte sector-one pattern,
and a cut before the already sealed future disk reaction. It exports the complete bounded image/resources,
reclaims the anchored source group and deletes its entire namespace. Two
concurrent fresh private branches independently recapture/audit at the unchanged
cut before replaying the same original held run and ACK. Their complete native
receipts, UART birth/byte rows, disk digest and write/direct-readback/flush markers
must equal the source continuation. The old foundation's first-read proof is
retained historically and cannot stand in for these new gates.

Pure helper cases and native RAM/queue primitive cases are mechanism evidence.
Only a matching actual Linux lifecycle/cold proof can populate this profile's
source-owned evidence record. Every ordinary common Ready, NativeArchive,
external Serial, complete typed diagnostic, broad device parity and CPU timing
admission remains false in this intermediate stage. Ordinary admission still
requires the separate model-aware common preparation/activation/history and
complete resource/device contract. Actual x86 full-system and timing/O3 device
qualification and later closed native networking/9p lifecycles remain work.

The present VirtIO frontend uses System.physProxy. Pinned native System
constructs that proxy over its system port; PortProxy sends functional packets
through that port. This is not a direct raw-RAM bypass, but it has no timed DMA
request/response/retry path. A later timing CPU/cache profile must independently
check functional cache visibility and add a source-selected timed DMA model when
claiming DMA/cache/bus latency fidelity. The new fixed backend delays do not
certify those timing properties. A native DmaPort-based extension would retain
pending packets, retries, ordered completions and their genuine event payloads
inside the same process-image closure before repeating the driver/cold gates.

The unchanged PID1 uses buffered pwrite 512 at offset 512 followed by fsync.
The source-derived expected native request is a sector-zero 4 KiB writeback.
The pinned kernel enables CONFIG_BUFFER_HEAD and CONFIG_ARM64_4K_PAGES;
block/bdev.c:set_init_blocksize grows this aligned 1 MiB device block size
to PAGE_SIZE, and block/fops.c:blkdev_writepages uses block_write_full_folio.
The successor must observe the actual original geometry and bytes before capture;
this expectation alone is not native proof.
The acceptance gate requires that complete payload: zero bytes outside
[512,1024), with the exact 512-byte pattern inside it. PID1 then performs its
independent 512-byte O_DIRECT sector-one readback. The first lifecycle attempt
reached INIT_READY but refused before capture because it incorrectly expected
a native sector-one 512-byte request; that failed source/log remains preserved.
The successor changes the evidence geometry, not the guest, native backend or
limits, and may qualify only after observing this entire original payload.
