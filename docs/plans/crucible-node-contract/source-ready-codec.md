# Source readiness correlation

The staged control protocol carries a 344-byte source receipt and a 128-byte
acknowledgement. Frame kinds 10, 11, and 12 distinguish the original offer, its
acknowledgement, and native consumption of that acknowledgement. Constructors
reserve capacity for the complete exchange before selecting this grammar.

The receipt binds the original scope, process and barrier generations, setup,
backend profile, implementation or launch, queue plan, clock observation, source
cut, and complete native closure transcript. The backend family and nonzero
closure codec version distinguish QEMU, gem5, KVM, and external implementations.
Acknowledgements hash every receipt byte under the versioned readiness domain.
The consumed acknowledgement carries the exact same body in its distinct frame.

Decoding and correlation supply no execution authority. A native issuer must
check the actual stopped source objects, retain their complete closure, consume
the original acknowledgement at that same cut, and publish that consumption
before the host can arm the node. Census fields describe the retained closure;
they do not establish ownership. Backend profiles define native counter units
and clock projections independently.

The codec passed 220 protocol controls with one ignored test, including seven
new controls for an independent big-endian vector, all four backend families,
malformed and changed bindings, complete receipt hashing, acknowledgement shape,
and precharged exchange capacity. Strict compiler and Clippy checks passed on
that frozen source. The imported successor changes clock rustdoc only. The
344-byte checked-in vector is a test fixture; raw execution evidence stays local.
Installed native issuance, consumption, and host arming remain separate
integration work.
