# Private bounded capture candidate

This is preparation only. It makes no deployment, completeness, authentication,
Native consumption, provider acceptance or runtime qualification claim.

## Files and selection

`baseline-proxy.mjs` is the exact existing proxy. `origin-capture.mjs` delegates
its HMAC/token/body/routing/manual-redirect logic unchanged. The only intentional
transport behavior addition is forwarding the caller AbortSignal into its one
outgoing fetch. The existing proxy catch still returns 401 for fetch failures;
that status does not distinguish authentication from transport failure.

`storage-entry.mjs`, generated by `render.py`, subclasses the independently
selected installed application class at the same Worker URL. It inherits queue,
scheduled and existing named Durable Object exports and calls super.fetch once.
No application URL, Host, body, signature, env binding or route is rewritten.
Nonselected methods/routes, public/bulk streams, GrantPartsBatch and credential
routes use the original Request without reading its body. Selection is exact
POST execute/capabilities, or the individually selected closed origin metadata
paths in capture.mjs. A query-bearing selected call is recorded unknown with no
body/frame capture; the original query is never retained.

Rendering requires an explicit closed current policy, already-created shared
namespace ID, and private bucket name. It is additive binding metadata, not a
provider operation or migration installer. Both roles must bind the SAME actual
namespace and corpus object. The caller must separately stage the exact selected
application shim/Wasm and current fixed proxy configuration; this renderer does
not fabricate them, provision bindings, read keys or invent a Ready window.
The policy's source/runtime pins describe the selected application. The separate
captureImplementationSha256 describes these five measured capture assets.

## Private corpus and byte images

One PrivateCaptureLedger Durable Object transaction debits the actual retained
body/frame bytes across roles and isolates BEFORE R2 effects. Maximum corpus is
512 MiB, including conservative metadata reservation (4096 window bytes, 16384
per admitted call). Maximum body image is 8 MiB. Pending/completion objects are
create once per ID/direction; an interrupted write does not free quota or permit
an ambiguous retry. A separate 16 MiB isolate-local retained-body memory ceiling
may truncate captures under concurrent pressure; it is NOT the global corpus
budget. It does not truncate the delegated stream. The ledger bounds admitted
calls to 8192 and emits dropped/overflow counters. Incomplete persistence or an
expired/unsupported/oversized observation cannot establish complete capture.

Private object layout, under the closed policy prefix:

- window.json: conservativeDebitedBytes, admittedCalls, droppedCalls, overflow;
  captureCompleteness is ALWAYS unknown, qualificationClaim false.
- <captureId>/pending.json: original fixed request metadata, captureState pending.
- <captureId>/<received_request|exposed_response>.json: directional receipt.
- <captureId>/<direction>-body.bin: independently observed bounded byte image.
- <captureId>/<direction>-<approved-protocol-header>.bin: private frame image.

captureId is an observer object identity, never an invented request/transport
correlation. Existing x-aos-storage-call-id and x-aos-fleet-request-id are
preserved; absent/noncanonical IDs remain null. Base metadata binds role,
purpose, corpus/window/source commit/tree/runtime/Native/Worker/capture asset
pins, method, exact path SHA256, queryClass and status. Neither URL nor query is
retained. Completion adds direction, state (eof/cancelled/overflow/unknown),
observedBytes and retainedBytes decimal strings, eof, imageKind, frameState,
startedAtMillis/finishedAtMillis, responseConsumptionClaim false. R2 receipts add
capturePersistence and privateImages [{name,key,bytes,sha256}]; values appear
only in private binary objects. Pending objects remain as start records; their
presence alone does not mean a completion is missing. Exported inventory must
join both direction receipts and mark missing or partial objects unknown.

Request provenance is independent_wrapper_received_bytes. Only complete EOF
images may be compared to an actual Native offeredRequestSha256/count and then
labelled matched_selected_receiver_byte_image by the independent adapter.
That comparison still lacks independent current receiver deployment/window
proof unless supplied separately; it is not authentication or completeness. Response
provenance is wrapper_exposed_reply_bytes, never Native consumption. The adapter
must independently join actual Native exposed prefix/count/hash/EOF and actual
MAC/authentication telemetry. No wrapper success can replace those joins.

Only x-aos-hybrid-ingress, x-aos-direct-upload-logical-signature,
x-aos-hybrid-upload-phase (closed metadata phase) or selected storage execution
x-aos-storage-work-signature are retained as bounded private frame objects.
No Authorization/Cookie/Google token/provider token/key headers are captured.
Route selection excludes delegated signed-URL replies; the body guard also
refuses non-UTF8, URL-query-bearing and credential-key-shaped body images,
without redaction or changing the delegated bytes. This guard is not a universal
secret classifier: the closed selected protocol and private export review are
still necessary. Refused images are unknown, not evidence of empty bodies.

## Limits of observation

Capture sink R2/DO operations are instrumentation traffic. Do not count them as
application provider requests or original committed bytes. Copying/hashing and
persistence can add observer latency; timestamps describe the observed stream
window, not a separately measured removable overhead. There is no per-call cost
or provider latency qualification in these local fixtures. Persisted summaries
may lag failed writes and cannot certify a complete window. A controller must
bound export, retain pending/dropped/overflow and actual export inventory, and
refuse completeness if any joins are unresolved. No capture export route or
public raw export is supplied. Private protocol assertions retain their actual
expiry/body/source scope; no new key, review, capability or admission is minted.

## Local checks

Source-built AOS Node executes capture-tests.mjs (13 stream/proxy/budget cases).
Source-built AOS Python executes render-tests.py (4 renderer/subclass cases).
Mocks exercise actual Request/Response streams and the ledger binary transport;
they are not Cloudflare/provider/Native consumption tests. No renderer output
from these fixture identities is an actual deployment or selected capture.

## Selected inventory is not the whole Native window

The origin allowlist observes only policy-selected POST publication/Direct
metadata paths. The following actual workload classes are intentionally absent:

| Request class | Capture selection | Evidence still required |
| --- | --- | --- |
| GET /-/instance, page/assets and other ordinary GET routes | Bypass | Actual route/method/query classification, current handler/source identity, authenticated ingress commitment and exact request consumption and reply offering counters for those calls; page response markup is not authentication proof. |
| POST /aos.hub.v1.IdentityService/WhoAmI | Bypass | Current authenticated identity result and its actual canonical request/reply body hash/count and correlation, independently verified against the selected application/source. Do not infer identity from rendered HTML or proxy status. |
| /-/auth/session-token and other session/login bridge traffic | Bypass | Independent fixed authentication/identity verdict plus exact canonical body commitment/count and EOF/correlation where retained by a selected safe observer. Token, cookie and Authorization values must not be exported or added to this capture. |
| Other RPCs, admin/bindings/custody/credential paths and bulk routes | Bypass | Separate authorized source-specific observation or unresolved coverage. Excluding a class does not prove its body count is zero. |
| Selected path with query, invalid/absent IDs, partial/oversized or dropped image | Unknown or incomplete | Exact supported query absence and current verified request/transport correlation, matching byte/count/EOF, complete private exported inventory and source/runtime/window joins. |

Even complete captures for every selected route cannot yield a whole-Native
inbound body inventory, a whole-window Native bulk zero assessment or complete
page workload qualification. A route not present in policy is unobserved, not
zero. Expected method/path classes and actual per-call coverage must be joined
with the independently selected Native ingress/body telemetry or another
approved observer; missing classes remain unresolved. Canonical body evidence
must use actual authenticated offered/consumed bytes, EOF and current source
verdicts. It must never substitute preflight values, wrapper counts or an HTML
marker for those results. This candidate does not broaden credential capture.

## Shared namespace script ownership

render(stage, policy, namespace_id, bucket_name, ledger_owner_script) requires
one explicitly supplied owner script. capture-bindings.json records
sharedNamespaceOwner {scriptName,className,namespaceId,entryModule} with class
PrivateCaptureLedger in origin-entry.mjs. The origin entry actually exports that
class. storage-entry.mjs deliberately does not add a competing local class; it
retains the application's existing named exports and consumes the supplied
cross-script namespace_id. Both consumers resolve idFromName(corpusId) on that
same namespace. There must not be a second storage-local ledger namespace.

This owner map is a declared deployment prerequisite, not a verified provider
fact. Before use, independent provider metadata must prove that namespace_id
belongs to the supplied origin owner script's PrivateCaptureLedger class, that
the deployed owner exports that class with the correct policy/private bucket,
and that both exact Worker scripts bind this same namespace. Existing app DO
migrations/exports stay unchanged. The renderer neither creates nor migrates a
namespace and cannot establish that mapping merely from a caller-supplied ID.
Its requiresIndependentProviderVerification field is always true. The focused
fixture imports both generated entry modules to verify owner export/consumer
absence and inherited application dispatch; it is not a provider wiring test.

## Explicit operator selection and tools

The origin transport takes a closed twelve-field operator-selected configuration:
`version`, `project`, `service`, `serviceUID`, `target`, `proxyOrigin`,
`publicOrigin`, `deploymentID`, `invokerEmail`, `invokerUID`, `startsAt`, and
`expiresAt`. There are no deployment-coordinate defaults. Target audience and
invoker subject/email checks use these exact selected values; the provider
verifies token signature and invocation authorization at the selected target.
Configuration grammar does not attest provider identity, IAM, namespace
ownership or deployment readiness. Public examples and tests use synthetic
coordinates only.

`render(..., node_tool={"file": selectedNode, "sha256": selectedDigest})` requires
a canonical immutable Node executable selected from independently established
AOS package provenance. It verifies the exact executable hash before invoking
the runtime policy validator and has no host-tool fallback. Path/hash checks
alone do not establish a source-built toolchain; the caller or future Nix
package must bind the actual AOS dependency. The local renderer suite requires
`AOS_CAPTURE_NODE_TOOL` containing that explicit closed reference. No executable
store path is embedded in these repository sources.

The capture implementation digest commits all five runtime assets. A source
change requires a new measured digest and selected policy; old private fixture
results or deployment identities cannot be relabeled. Whole hosted coverage
stays incomplete, and unavailable independent Native bulk accounting remains
null, never zero.
